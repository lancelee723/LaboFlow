## 1. 项目背景与概述

### 1.1 业务背景

管理咨询团队的工作本质是「信息密集型交付」：行业研究、专家访谈、数据分析、模型搭建、报告与 PPT 撰写。2025-2026 年，AI Coding Agent（Codex、Claude Code、ZCode 等）已经证明「Agent Harness + 工具调用」范式能将 LLM 转化为可靠的数字劳动力，但现有产品几乎全部面向**软件开发者**：

- 交互语言、示例、工具链（git、终端、IDE）均为编程场景设计，非技术背景的顾问上手门槛高；
- 缺乏咨询行业的方法论沉淀（MECE、金字塔原理、假设驱动）与交付物工程（PPT/Excel/Word/PDF）的原生支持；
- 面向个人开发者，缺少 2B 团队所需的组织账号、共享工作区、模型统一接入、用量与成本管控、审计合规能力；
- 数据边界不清晰，咨询行业受客户保密协议（NDA）约束，对「内容是否离开组织」极度敏感。

### 1.2 问题与机会

**问题**：咨询团队目前只能用面向开发者的通用 Agent 工具「凑合」，存在上手难、方法论无法沉淀、模型账号与成本无法统一管理、团队协作只能靠截图复制的现状。

**机会**：以开源 Agent 引擎（Pi，MIT，102k stars）为内核，用 Electron 构建跨平台桌面工作台，向上叠加咨询行业 Skill 生态与 2B 组织能力（账号/权限/共享区/模型网关/配额），以「每组织独立部署」的私有化模式交付——数据不出组织，天然契合咨询业保密要求。同类先例已验证技术路线（Proma 基于 Pi+Electron 成功构建）与商业模式（Proma 商业版、腾讯 WorkBuddy 均以团队配额+组织分发为核心付费点）；**Cortex Desktop（闭源，Pi 0.84 + Electron，个人向）进一步验证了 Pi 内核可承载完整商用桌面产品（语音/浏览器/研究/产物引擎），其 worker 进程内嵌引擎的架构与设计体系被吸收进本 PRD 与 SPEC v1.2（见《Cortex 逆向调研报告》）**。

### 1.3 产品定位与价值主张

**一句话定位**：为管理咨询团队定制的 AI 工作台——像 Codex 之于程序员，LaboFlow 之于咨询顾问。

**价值主张**（对三类买家用不同的话说）：
- 对**顾问（使用者）**：一个会做研究、跑数据、写报告、做 PPT 的专家团队，方法论可复用，交付物质量稳定；
- 对**团队负责人（决策者）**：团队方法论（Skill/专家/提示词）沉淀为组织资产，新人开箱即用；用量与成本透明可控；
- 对**组织 IT（管理者）**：私有化部署、统一模型接入、按团队配额管控、全量审计，满足客户保密协议要求。

**产品形态**：Electron 桌面客户端（Windows x86_64 / macOS Apple Silicon / Linux x86_64）+ Docker 私有化服务端（Linux x86_64）+ Web 管理控制台。**客户端不登录即可完整使用（本地优先），登录后叠加组织能力。**

### 1.4 产品目标与成功指标

**业务目标**（发布后 6 个月）：
1. 在 ≥3 个试点咨询团队（合计 ≥30 名顾问）中日常使用；
2. 单团队周均完成 ≥100 个有效会话任务（研究/分析/文档类）；
3. 组织 Skill 库沉淀 ≥20 个团队自有技能。

**产品目标与北极星指标**：

| 指标类型 | 指标 | 目标（GA 后首个季度） |
|---|---|---|
| 北极星 | 周活跃会话数（组织维度，去重用户发起的会话） | ≥300/组织 |
| 规模 | 周活跃用户（WAU，登录用户） | ≥70% 组织成员 |
| 质量 | 会话任务完成率（用户未中途放弃） | ≥80% |
| 成本 | 组织 Tokens 成本可见率（走网关比例） | ≥90% 新会话使用组织模型 |
| 生态 | Skill/插件安装用户占比 | ≥60% |
| 稳定 | 客户端崩溃率（会话数/崩溃数） | <0.5% |

### 1.5 名词术语

| 术语 | 定义 |
|---|---|
| Harness（引擎） | Agent 运行框架：调度 LLM、执行工具、管理会话与上下文。LaboFlow 采用开源 Pi Agent 为内核 |
| 会话（Session） | 一次与 Agent 的连续对话及全部工具调用轨迹 |
| 项目（Project） | 绑定本地文件夹的工作空间，可包含多个会话 |
| Skill | 以 SKILL.md 描述的可复用能力包（Agent Skills 开放标准，兼容 Claude 生态） |
| MCP | Model Context Protocol，外部工具服务器接入协议 |
| 专家（Expert） | 用户定义的具名子 Agent，由 Agent.md（能力定义）+ Soul.md（人格定义）构成 |
| 工作区（Workspace） | 服务端共享空间：共享会话 + 交付物库，面向团队成员授权 |
| 交付物（Deliverable） | 工作区文件区的产出物（PPT/Excel/Word/PDF 等） |
| 产物（Artifact） | 会话内 Agent 产出的文件/图表/网页等（v1.2）：卡片化呈现、带版本，可入交付物库（FR-C-51） |
| 渠道（Provider/Channel） | 一个模型 API 接入配置（内置供应商或自定义） |
| 网关（Gateway） | 服务端模型 API 中转与计量组件 |
| 虚拟 Key | 网关下发给客户端的凭据，组织真实上游 Key 不出服务端 |
| 权限模式 | 会话级 Agent 行为管控档位，共四档（见 4.1.3） |

## 2. 用户与场景分析

### 2.1 目标用户画像

| 画像 | 角色 | 特征 | 核心诉求 |
|---|---|---|---|
| 顾问 Analyst/Consultant | 使用者（主力） | 非技术背景，Excel/PPT 熟练，对终端/编程陌生 | 低门槛完成研究/分析/文档；能看懂 Agent 在做什么；结果可信可追溯 |
| 项目经理 EM/ED | 使用者+管理决策者 | 带团队交付，对质量与保密负责 | 方法论沉淀复用；任务并行提效；成本可控；交付物审阅 |
| 团队知识管理员 | 轻管理 | 维护组织 Skill/专家库 | 方便发布/更新组织资产，控制版本 |
| 系统管理员（IT） | 部署与治理 | 负责私有化部署、账号、模型接入 | 一键部署；统一接入模型；配额与审计；少运维 |

### 2.2 核心用户故事

**顾问（本地模式，P1）**
- US-01 作为顾问，我想把客户的项目文件夹设为一个项目，在多个会话里分别做行业研究、数据清洗、slide 起草，以便在同一上下文里持续工作。
- US-02 作为顾问，我希望 Agent 改文件前先给我看 diff（变更前确认模式），客户数据我不敢让它乱动；但我也要能切到自动编辑档提速。
- US-03 作为顾问，我想把访谈录音转写稿拖进会话，让 Agent 按「专家访谈纪要」Skill 输出结构化洞察。
- US-04 作为顾问，我想创建一个「战略分析师」专家（写好 Agent.md 和 Soul.md），把机械的研究任务指派给它后台跑，我继续干别的。
- US-05 作为顾问，我想看到本周我花了多少 tokens、花在哪些模型上，心里有数。

**项目经理（组织模式，P2）**
- US-06 作为项目经理，我想把「某客户市场规模测算」会话共享到团队工作区，设为「可参与」，让associate 接力补充数据。
- US-07 作为项目经理，我想在共享会话里实时看到同事与 Agent 的推进过程（旁观），需要时插入一句话纠偏。
- US-08 作为项目经理，我想让 Agent 产出的 PPT 初稿自动落到工作区交付物库，团队成员都能预览、下载。
- US-09 作为团队负责人，我想发布组织 Skill「公司 Slide 模板规范」和「MECE 议题树工作法」，全员一键启用。

**系统管理员（P2）**
- US-10 作为系统管理员，我想接入公司的模型账号（如 DeepSeek/GLM API），配置给指定团队，并限制每团队每月 Token 上限。
- US-11 作为系统管理员，我想批量创建员工账号、指定初始团队管理员，员工首次登录强制改密。
- US-12 作为系统管理员，我想在 Web 控制台看到各团队的用量趋势与配额余量，配额将触顶时收到告警。

### 2.3 竞品对标结论摘要

（详见调研报告）Codex：权限双轴与审阅队列思想可借鉴；ZCode：权限四模式与插件市场兼容语义直接沿用；FreeBuddy（MIT）：Electron 三平台打包与用量卡片范式；Proma（AGPL，仅借鉴模式）：Pi 内嵌架构、Channel 配置 UX、组织资产分发商业形态；WorkBuddy：admin console 与配额运营面板范式；**Cortex（闭源，逆向对标）：Pi worker 进程隔离架构、会话产物工作台（时间线/产物卡片/版本/分屏对比）、Slide 引擎与深度研究管线形态、暖中性灰视觉体系（附录 D 设计 token 基准）——只借鉴实现思路与视觉规格，不接触其代码与美术资产**。差异化空档：**无一产品同时具备「咨询行业工作流 + 私有化组织协作 + 模型网关配额」**（Cortex 的团队化绑定其私有云且仅 macOS，反证私有化自托管路线的稀缺性）。

## 4. 功能需求详述

> 每个功能按「描述 / 用户故事 / 交互与规则 / 异常与边界」展开。界面线框见附录 A。需求编号对应 3.2 总表。

### 4.1 客户端（LaboFlow Desktop）

#### 4.1.1 工作台与项目管理（FR-C-01/02）

**描述**：客户端首页为工作台。用户可创建「项目」并指定本地文件夹作为项目路径；每个项目下可开设多个会话；会话可随时切换、重命名、归档、全文搜索。

**交互与规则**：
1. 新建项目 → 系统文件夹选择器 → 首次打开该文件夹弹出**信任确认**（说明将允许 Agent 读取/写入该目录及运行其中的配置，决策持久化，可撤销）。未信任目录只读。
2. 项目卡片显示：名称、路径、会话数、最近活跃时间、绑定的工作区（P2）。
3. 会话列表按「最近活跃」排序，支持置顶；会话标题默认取首条用户消息摘要，可手动改名。
4. 会话搜索：匹配标题与消息全文（本地索引）。
5. 项目级配置：项目名、默认权限模式、默认模型、项目 AGENTS.md（在项目页可查看/编辑）。
6. 关闭项目 ≠ 删除数据；删除项目需二次确认，可选是否保留会话归档。

**异常与边界**：项目文件夹被移动/删除 → 会话仍可打开（只读，提示路径失效，可重新绑定路径）；文件夹为系统敏感目录（如用户主目录根、磁盘根）→ 警告但允许。

#### 4.1.2 会话交互（FR-C-03/04/05）

**描述**：会话视图是核心工作界面：三栏布局（左：项目与会话导航；中：消息流；右：上下文面板）。消息流包含用户消息、Agent 回复（流式）、工具调用卡片、审批卡、计划卡、子Agent 卡片。

**交互与规则**：
1. 输入区：多行输入、附件按钮（图片/文档）、@文件引用（项目内路径补全）、思考等级选择（off/低/中/高）、模型选择器（展示渠道+模型，含组织渠道标记）、权限模式选择器、发送。
2. 附件：图片直接进上下文；文档（PDF/DOCX/XLSX/PPTX/TXT/CSV）由本地解析器转为文本/表格摘要后进入上下文；超大文件（>20MB）提示仅索引目录与摘要。
3. 流式输出中可**打断**（Steer：打断后补充指令）或**排队追问**（当前轮结束后自动发送）。
4. 工具调用卡片：默认折叠显示一行摘要（工具名+参数摘要），展开看完整输入/输出；文件修改显示 **diff 视图**（unified/分栏双模式）；长输出虚拟滚动。
5. 计划门：计划模式下 Agent 先产出计划卡（可增删改任务项），用户「批准执行 / 继续修改 / 放弃」。
6. Todo 进度：Agent 生成的任务清单在消息流内以进度组件渲染，右侧面板同步汇总。
7. 会话操作：导出（Markdown/HTML）、复制为 fork（复制当前会话到新会话继续）、压缩上下文（手动触发，显示压缩前后 token 数）。
8. 子Agent 卡片：显示子Agent 名称/状态/耗时/token 消耗，可展开查看其内部会话（只读）。
9. **免项目聊天**：工作区菜单「不在项目中工作」，侧边栏与项目会话并列管理（置顶/分组/归档/拖拽）；无 Git 分支选择器；首条消息后不可转为项目会话；产生的文件留在磁盘并在会话结束提示清理。
10. **划选追问**：在回复/思考/代码/工具输出中选中片段 → 浮动工具栏 →「添加到当前任务」（引用旁挂草稿）或「在辅助对话中提问」；流式输出中划选冻结文本；仅支持单行内选择；引用长度/条数/总量超限显式提示、不静默截断。
11. **辅助对话（/side、/btw）**：不作为消息发送的命令；携带主会话全部历史作为模型上下文，但 UI 时间线独立从空白开始；具备完整工具与权限确认能力；不继承 goal/发送队列/后台任务；每个主任务单窗口限一个；主任务运行中或等待确认时仍可从「+」菜单进入（浮动工具栏此时不可用）；随主任务关闭不可恢复。
12. **会话分叉**：悬停「稳定完成」的 Agent 回复 → 分叉按钮；继承分叉点前历史与当时模型/思考等级/goal 进度；不回滚磁盘文件；队列与后台任务不复制；上下文压缩进行中禁止分叉；新会话标题「Fork of <原题>」。
13. **#会话引用**：`#` 把历史会话链接为当前任务上下文（自动摘要注入）；与 @文件、/命令、$技能 在输入框内联并列。
14. **长文本粘贴**：超阈值的长文本自动转为附件条目（完整内容仍发送），避免输入框膨胀。

**异常与边界**：模型 API 报错 → 内联错误卡 + 重试按钮（自动重试 2 次，指数退避）；上下文将满 → 主动提示并建议压缩；断电/崩溃重启 → 会话自动恢复到最后完整条目（写入即持久化）。

#### 4.1.3 权限管理：四模式 + 组织策略下限（FR-C-06/07/08）

**描述**：沿用 ZCode 语义的四档会话权限模式，登录组织后叠加管理员下发的策略下限。

| 模式 | 语义 | 文件读取 | 文件写入 | 命令执行 | 网络（浏览器/MCP） |
|---|---|---|---|---|---|
| 变更前确认 Confirm Changes | 最严格（**默认档**） | 项目内自动；项目外询问 | 每次变更前展示 diff 请求批准 | 每条命令前请求批准 | 每次请求批准 |
| 自动编辑 Auto Edit | 平衡 | 项目内自动 | 项目内自动（可撤销） | 危险命令（删除/覆盖/网络安装等，内置黑名单）询问，其余自动 | 自动，敏感站点（登录页/支付）询问 |
| 计划模式 Plan Mode | 先批后做 | 自动（只读阶段） | 禁止，直到计划获批 | 禁止，直到计划获批 | 禁止，直到计划获批 |
| 完全访问 Full Access | 最宽松 | 自动 | 自动 | 自动 | 自动 |

**交互与规则**：
1. 模式在会话级设置，输入区旁选择器一键切换（输入框聚焦时 **Shift+Tab** 循环切换），当前模式常显（色彩编码：确认=琥珀、自动=蓝、计划=紫、完全=红）。
2. 审批卡内容：动作类型（写文件/执行命令/网络访问）、目标、diff 或命令全文、风险提示；操作五档：**允许 / 始终允许 / 拒绝 / 始终拒绝**，部分场景提供细粒度 **允许本会话 / 始终允许本项目**；「始终允许/拒绝」与「本会话/本项目」记录到对应层级的会话策略，会话（或项目）结束失效。
3. 审批等待归属当前会话：切换会话再切回，待审批状态保留；审批等待中输入区阻塞。
4. **普通提问 5 分钟倒计时自动继续**：Agent 提出选择题类普通问题时默认 5 分钟倒计时，无人作答则按自判断继续并在历史标注「未回答，已自动继续」；任何用户交互（悬停面板/开始选择/点击秒数/停止计时）**永久停止**该倒计时；设置→常规可关闭（默认开，关闭不追溯）；**权限请求与计划审批不倒计时（无限等待）**。
5. **组织策略下限**（P2）：组织管理员可对「全部 / 指定工作区绑定的项目」下发最低模式（如：涉客户数据项目不得低于「变更前确认」）。客户端实际生效模式 = max(用户选择, 策略下限)（按严格度比较）；被策略抬高时 UI 明示「由组织策略生效」。
6. 权限引擎对所有工具调用统一收口：内置工具、MCP 工具、子Agent 的调用同受本会话策略约束（子Agent 继承父会话模式，不得越权）；完全访问与高权限档下工具栏持续显示风险提示。

**异常与边界**：审批等待中用户关闭 App → 该动作不执行，重启后可从待审批队列恢复；完全访问模式下执行高危命令（rm -rf 类）仍做一次性确认（内置不可关闭的兜底规则，仅覆盖明确破坏性命令特征）。

#### 4.1.4 Skills（FR-C-09）

**描述**：兼容 Agent Skills 开放标准（SKILL.md）。Skill 来源：内置（官方精选，含咨询行业包）、插件市场安装、本地文件夹导入、组织库下发（P2）。渐进式披露：仅 name/description 注入系统提示，命中任务时加载全文。

**交互与规则**：
1. 管理页（设置 → Skills）：列表（来源标签：内置/市场/本地/组织）、启用开关、版本、更新、卸载；详情页展示 SKILL.md 全文与文件清单。
2. 作用域：全局（所有项目）或项目级（仅该项目会话加载）。
3. 冲突：同名 Skill 按优先级组织库 > 项目 > 全局 > 市场 > 内置；市场安装时可预览将覆盖项。
4. 组织 Skill（P2）由服务端下发，客户端只读，不可本地修改（保证团队方法论一致性），可整体停用。

#### 4.1.5 MCP（FR-C-10）

**描述**：支持 stdio 与 HTTP(SSE/Streamable HTTP) 两类 MCP 服务器。配置来源：手动添加、插件市场安装、导入既有配置（JSON 粘贴，兼容常见 mcpServers 格式）。

**交互与规则**：
1. 管理页：服务器卡片（名称/类型/状态：连接中/正常/失败/已停用）、启动/停用、编辑（命令与参数/URL/环境变量/超时）、重连。
2. 服务器详情：工具列表（名称/描述/启用开关）；工具调用纳入权限引擎管控。
3. 健康检查：连接后拉取工具列表；失败显示原因（命令不存在/URL 不通/协议错误）；重启客户端自动重连已启用的服务器。
4. 安全：环境变量中的密钥走系统加密存储；stdio 子进程在项目信任目录内运行时给出提示。

#### 4.1.6 插件市场（FR-C-11/12）

**描述**：兼容 Claude 插件市场清单格式（marketplace 清单 + 插件内 skills/MCP/commands 资源），支持手动添加第三方市场源（superpowers、PPT-Master 等 git 仓库或本地路径）。

**交互与规则**：
1. 市场管理页：市场源列表（官方默认源 + 用户添加源：git URL / 本地路径，含启停与刷新）；源内插件浏览（搜索/分类/详情截图与 README 渲染）。
2. 安装：预览插件将安装的资源清单（几个 Skill/MCP/命令、将写入哪些目录）→ 确认安装（含安全提示：第三方代码与配置）。
3. 更新：版本对比 + 一键更新；卸载干净（移除资源并保留用户数据）。
4. 已安装插件统一在「插件」页管理（与 Skills/MCP 管理页互通：插件资源在对应页面出现并标注来源插件）。
5. P3：hooks 与 agents 类型资源兼容（解析并映射到 LaboFlow 的事件系统与专家系统）。

**异常与边界**：源不可达 → 缓存目录可继续安装已缓存插件；清单格式不兼容 → 明确报错并给出资源类型不支持说明。

#### 4.1.7 子Agent 与专家团队（FR-C-13/14/15/16/17）

**描述**：三层递进。①基础子Agent（P1）：内置「通用/探索」两类，会话内派发后台分支任务；②个人专家（P2）：用户以 Agent.md + Soul.md 定义具名专家，可单独指派；③团队（P2 指挥官 / P3 圆桌）：多专家协同。

**交互与规则**：
1. **基础子Agent**：会话内通过指令或 UI「派发子任务」→ 选类型（通用=可读写项目内文件；探索=只读检索）→ 后台运行卡片（进度/耗时/tokens）→ 完成后结果回主会话，可展开查看子会话全文。
2. **专家定义**：专家 = Agent.md（职责、可使用工具白名单、默认模型与思考等级、输出规范）+ Soul.md（人格、语气、立场，如「你是资深麦肯锡风格的战略合伙人，直言不讳，重数据轻形容词」）。创建向导含模板（战略分析师/数据分析师/行业研究员/Slide 工程师/访谈洞察专家/审稿人）。
3. **专家指派**：会话内 @专家名 或在任务卡中选择；专家在独立子会话中执行，继承项目上下文摘要与权限模式。
4. **指挥官模式团队**（P2）：用户（或主 Agent）把任务拆解指派给多个专家，专家间不直接对话，结果由主会话汇总整合；团队页显示成员状态板。
5. **圆桌讨论轮**（P3）：在团队任务中开启「讨论轮」，指定专家与轮次上限（默认 3），专家间可见彼此发言并直接讨论，轮次结束由主持人（主 Agent 或用户）收束结论。
6. **组织专家库**（P3）：团队知识管理员把个人专家发布到组织库，全员可安装使用（只读副本）。

**异常与边界**：子Agent 失败不阻断主会话（卡片标红 + 重试）；专家并发上限（默认 3，可配）防 token 失控；团队任务总 token 预算提示（超阈值预警）。

#### 4.1.8 定时任务（FR-C-18/19）

**描述**：客户端调度器，语义对齐 ZCode 自动化：结构化频率选择器（无 cron 表达式 UI，高级模式可选直接编辑）、任务持久化跨重启存活、**错过不补跑（记「跳过」）**、单任务单并发、全局 20 个任务上限。

**交互与规则**：
1. 创建入口三种：自动化页表单；会话内创建（**任务绑定当前会话，此后每次触发结果追加进同一会话**，会话内出现任务卡片可跳转）；模板预填（内置 4 个咨询向模板：工作日晨会动态、每日风险扫描、周五交付简报、周三文档同步检查——默认只读分析导向）。
2. 任务定义：标题、执行计划（**结构化选择器**：单位 时/天/周/月/年 × 间隔每 N × 具体点位 星期几/几号/几点几分；每月支持「按日期」或「按第几个星期几」；折叠为短摘要可再编辑；高级模式可直接编辑 cron，本地时区）、指令模板（支持 {{date}} 等变量）、目标项目（仅本地项目）与模型/思考强度、权限模式（任务运行中遇审批则**自动降级跳过并记录待审批**——无人值守不得静默越权）、结束条件（默认无限 / 结束日期，到期转「已完成」）、启停。
3. **立即运行**：不扰动计划、计数与启用状态；上一条仍在运行时不排队（提示「正在运行」）。
4. 列表页：任务卡片（下次运行时间：一个月内显相对时间、超月显确切日期；状态：运行中/已暂停/已完成/失败）；详情页「设置/历史」两 tab；历史每条记录为 成功/失败/**跳过**（休眠或未运行错过，**不补跑**）三态，可跳转对应会话。
5. **全局上限**：所有项目合计 20 个任务（暂停/完成/失败均占额，删除任务定义才释放）；Agent 在会话内创建任务撞上限时停下告知，不得擅自删除已有任务。
6. 「保持唤醒」全局开关（与闲时任务共享）；任务完成桌面通知（可配置），结果写入绑定会话或交付物库（P2）。
7. 连续失败 3 次自动暂停并通知。

**异常与边界**：App 未运行或休眠期间错过的触发 → 记「跳过」**不补跑**（与 ZCode 语义一致）；执行中 App 退出 → 该次记录「中断」；连续失败 3 次自动暂停并通知；会话被删除时绑定任务提示重绑或转新建会话。

#### 4.1.9 用量统计（FR-C-21/22）

**描述**：本地记账 + 组织记账双口径图表。维度：时间（当日/近 7 日/近 30 日）、模型、渠道（组织/个人）、会话、专家。

**交互与规则**：
1. 图表页（对齐 ZCode 使用统计形态）：按天 Token 趋势折线（悬停显示按模型每日明细）、**活跃热力图**、**模型用量排行与环图**、组织 vs 个人渠道占比饼图、指标卡（会话数/消息数/活跃天数/**当前与最长连续使用天数**/**高峰使用时段**）、表格（Top 会话/专家消耗）；时间筛选：全部/近 30 天/近 7 天（当日快捷入口）。
2. 记账口径：所有经客户端发起的调用均本地记录（模型、tokens、成本估算、时间戳、会话 ID）；**走组织网关的调用以服务端计量为准**（登录后拉取校准）；个人 key 的调用内容与用量均不上报。
3. 配额余量（P2，对应 ZCode「编程套餐」面板位置）：走网关调用时展示组织配额面板——本人/本团队各周期余量、重置倒计时、上下文构成（消息/工具占比）；余量 <20% 黄色、<5% 红色告警（ZCode 的「额度重置卡」体系不适用，配额按周期自然重置）。
4. 导出 CSV。

#### 4.1.10 Browser Use 与 Computer Use（FR-C-23/24）

**Browser Use（P1）**：
1. 形态：内嵌受控浏览器（Electron Chromium，独立登录态 profile，不共享用户日常浏览器），Agent 经 CDP 执行导航/点击/输入/滚动/截图/提取；默认启用（设置可关，开关仅对新会话生效）。
2. **标签认领制**：Agent 默认只操作自己打开的标签；用户手动打开的标签须显式「认领」后才可被接管；标签跨会话留存直到关闭。
3. 授权页：总开关、站点范围（不限制/白名单）、**Chrome 数据快照导入**（一次性导入最近 Chrome Profile 的 Cookie+LocalStorage；不同步不改动 Chrome、不读密码；macOS 需钥匙串权限，Windows 首版暂缺并在 UI 标注）、数据清理两级（清缓存保留登录态 / 清全部二次确认不可撤销）。
4. 会话内浏览器面板：Agent 新建标签自动展开、操作实时可见；地址栏/导航/DevTools；**元素点选按钮**把元素（标题/URL/文本/选择器/位置/安全 HTML 摘要）选为聊天上下文；视口切换（如 375×812）；人工接管（暂停 Agent 控制，操作后交还）。
5. 安全规则：**网页中的文字不作为指令**（仅用于定位元素与理解状态，防 prompt injection）；不可逆操作（提交/下单/发消息）受权限模式管控（见 4.1.3）；暂不支持文件上传类表单（UI 明示）。

**Computer Use（P3）**：
1. 形态：可操控本机其他应用（辅助功能优先，视觉回退）。默认关闭。
2. 授权页分平台：macOS 引导开启「辅助功能 + 屏幕录制」TCC 权限（深链至系统设置并检测授权状态）；Windows 无 TCC，做「范围确认」（可操控应用白名单/显示器范围）+ 每次会话显式开启。
3. 执行时屏幕高亮提示当前被操控区域；紧急停止快捷键。

#### 4.1.11 模型接入 BYOM（FR-C-25/26）

**描述**：Channel（渠道）抽象。内置供应商（DeepSeek、智谱 GLM、Kimi、Qwen、OpenAI、Anthropic、Google、OpenRouter、Ollama 本地等）**只需填 API Key**；自定义渠道支持 OpenAI 兼容/Anthropic/Gemini 三类协议 + BaseUrl。

**交互与规则**：
1. 渠道管理页：渠道卡片（供应商 logo、协议类型、状态、模型数）；新建向导：选预设或自定义 → 填 Key/BaseUrl → **测试连接**（即时反馈）→ **从供应商拉取模型列表** → 勾选启用模型（可设默认模型与思考等级映射）。
2. BaseUrl 自动补全 /v1 等常见后缀；Key 以系统加密存储，界面仅显示尾 4 位。
3. 组织渠道（P2）：登录后自动出现「组织提供」渠道（网关地址 + 虚拟 Key 自动配置，用户无感）；组织渠道与个人渠道在模型选择器中并列，标注来源；用户可在设置中选择默认优先（组织/个人）。

#### 4.1.12 登录与组织（FR-C-27）

**描述**：默认免登录本地使用。登录页输入组织服务器地址 + 管理员分配的账号密码；首次登录强制改密。

**交互与规则**：
1. 登录：服务器地址（https，含端口）、用户名、密码；记住地址；登录后拉取：用户角色、所属团队、可用工作区、组织模型配置、组织 Skill 清单、策略下限。
2. 首次登录（must_change_password 标志）→ 强制改密向导（强度校验：≥10 位含字母数字）→ 改密成功方可进入组织模式。
3. 账号菜单：组织名/团队/角色展示、组织资源入口、登出。登出后共享区数据本地缓存清除（可配置保留天数），本地数据不受影响。
4. Token 过期自动刷新；服务端不可达 → 降级本地模式并横幅提示。

#### 4.1.13 团队工作区（FR-C-28/29/30）

**描述**：登录后可见「工作区」导航。工作区 = 服务端共享空间（共享会话 + 交付物库）。权限三级：**仅查看 Viewer / 可参与 Contributor / 管理 Manager**。

**交互与规则**：
1. 工作区列表（我有权限的）：名称、成员数、最近活跃；工作区详情：共享会话 tab + 交付物库 tab + 成员 tab（Manager 可管理）。
2. **共享会话（回合制串行）**：任一「可参与」成员在会话中发言 → 会话进入「执行中」，其余成员**实时旁观**（WS 推流：消息、工具卡片、状态），执行中输入框替换为「排队发言」；当前回合结束（Agent 空闲）→ 队列中的下一条自动发出或空闲开放发言。会话顶部显示当前发言人与等待队列。
3. 发起人可把本地会话「共享到工作区」（选择目标工作区与默认权限）；共享后该会话以服务端为权威，本地留存缓存副本；可「取回为本地会话」。
4. **交付物库**：文件列表（类型图标/大小/上传人/时间/来源标记：人工上传 or 会话产出）；预览（PDF/Office/图片/文本）；下载；上传（拖拽）；Agent 可在会话中直接把产出物写入交付物库（经权限引擎批准）；版本：同名覆盖生成 v2/v3 历史版本，可回滚。
5. 权限矩阵：

| 操作 | Viewer | Contributor | Manager |
|---|---|---|---|
| 查看会话/文件 | ✅ | ✅ | ✅ |
| 发言/排队、上传文件、Agent 写入交付物 | ❌ | ✅ | ✅ |
| 分享新会话、重命名、删除会话/文件 | ❌ | 本人创建的 | ✅ |
| 成员与权限管理、工作区设置 | ❌ | ❌ | ✅ |

6. 创建/删除工作区：团队管理员及以上（见 4.2.2）。

**异常与边界**：网络中断 → 旁观流断线重连（增量拉取）；发言中客户端崩溃 → 服务端 90 秒无心跳自动释放回合锁；并发冲突（两人同时点发言）→ 服务端按先到先得，后者转排队。

#### 4.1.15 命令与命令中心（FR-C-36/37）

**描述**：Command 为一等公民。`/` 面板分「命令」与「技能」两分组，关键字筛选；命令可带参数提示；`$技能名` 以标签形式调用 Skill。

#### 4.1.16 目标模式 Goal Mode（FR-C-39）

**描述**：面向长任务：`/goal` 设定目标后 Agent 逐轮自主推进，每轮结束自动校验，确认达成才收尾——把「反复催 continue」变成「设目标等结果」。

**交互与规则**：
1. 命令集：`/goal` 查看 | `/goal <描述>` 设定（覆盖） | `/goal replace` | `/goal pause` | `/goal resume` | `/goal clear`；每会话同时仅一个 goal。
2. **逐轮证据校验**：每轮结束跑独立 verification pass；未达成 → 产出下一步动作并自动开下一轮；达成 → 收尾总结。**只认可验证产物**（文件/命令输出/测试结果），计划、todo、耗时、「像结论的回复」均不算；存在未完成 todo 时不得判完成。
3. 右侧上下文面板显示 goal card（目标+已用时长）+ 按迭代分组的 checklist（条目固定挂首次出现的轮次；每轮标题来自上轮校验的下一步动作）。
4. 中途干预支持自然语言（换向/暂停/放弃 → 自动映射 replace/pause/clear）；按停止自动 pause；goal 状态随会话持久化，重启恢复断点。
5. 终止三条件：校验达成 / 用户暂停或清除 / 该 goal 的用量上限触顶（创建时可配 token/轮数上限）。
6. 计划模式与运行中不可设 goal（UI 显因）；推荐搭配「完全访问/自动编辑」减少中断。

#### 4.1.17 项目记忆 Memory（FR-C-41）

**描述**：项目级长期记忆：用户「只想说一次」的偏好与约定（4 类：用户偏好/对 Agent 的反馈/项目约束/外部参考），自动沉淀、新会话自动携带。刻意不记：代码结构、Git 历史、AGENTS.md 已有内容、临时信息。

**交互与规则**：
1. 设置→常规开关，**默认关闭**；仅对新会话/重启恢复的会话生效；作用域=项目；仅主对话读写（子Agent/专家不读不写）；远程工作区不支持（P4 之前）。
2. **提取**：每轮成功结束后后台回顾，值得保留才写入事实文件并更新索引；提取与召回的额外 token 消耗在用量统计可见。
3. **召回**：同项目新会话自动加载索引（大小上限，超限截断，条目保持精短）。
4. 自然语言管理：「记住，…」立即保存；「忘掉…」删除；可问「你记住了哪些」。
5. **管理页（对 ZCode 的改进项）**：设置→记忆，按项目查看/编辑/删除条目（ZCode 当前无应用内管理）。
6. 存储：本地 Markdown（`MEMORY.md` 索引 + 每事实一文件，路径约定见 SPEC），可手动编辑；绝不上传（登录组织亦不上传，后续可选组织级共享记忆列为 P4+）。

#### 4.1.18 仓库 Wiki（FR-C-40）

**描述**：项目代码库/资料库的架构导读：Agent 通读后生成带**源码行号跳转**的参考文档（项目定位/主流程/核心模块/数据流/扩展点/风险点；排除安装部署等通用章节），随变更自动保鲜。

**交互与规则**：
1. 入口：文件树顶部仓库名旁图标，全屏打开；生成选项四项（语言中/英默认随界面、模型默认随聊天模型可临时换、生成图表默认开、失败重试次数默认 0）。
2. 过程状态：分析→目录→页面→保存；**生成中即可阅读已完成页**；可随时停止（已完成页保留）；单页失败不中止整体。
3. 阅读器：两栏（项目/TOC+正文，分隔可拖、窄屏堆叠）；元数据（分支/语言/更新时间/commit/页数）；结论跳转工作区文件与行号；Mermaid 主题适配与缩放。
4. **自动刷新**：每轮会话结束检查代码是否实际变更，变更才刷新；「重新生成」手动触发。
5. **隐私过滤**：不进模型上下文——.git、依赖、构建产物、缓存、.gitignore 命中、文件名含敏感词（token/secret/credential/password）的可疑文件、symlink 目标；逐层按需读取，不提供预构建清单。
6. 存储：本地 `wiki.json`（全部页面 Markdown+引用），不写入项目目录；每仓库同时仅一个生成任务；仅一种语言版本（换语言覆盖）。
7. 咨询场景适配：不仅限代码仓库——资料文件夹（访谈纪要/数据表/行业报告）同样可生成导读 Wiki。

#### 4.1.19 编辑历史对话（FR-C-35）

**描述**：修改已发送的用户消息让 Agent 按更新后上下文继续；配合文件级 Undo/Reapply，把「说错话」的纠错成本从重开任务降为原地改一句。

**交互与规则**：
1. **仅最新一轮用户消息可编辑**（绝不修改 Agent 回复）；运行中/有排队消息不可编辑；编辑时可继续用 @ / / / $。
2. 提交=按更新消息重发（保留模型/工作区/分支/上下文）。
3. **「对话+文件重置」**：恢复本轮被更改文件至改前状态 + 以修正消息重发；任一文件无法安全恢复（用户手改过等）→ 提示可选「仅重置对话并发送」；运行中/压缩中/无可恢复更改时不可用。
4. **Undo/Reapply（全有或全无）**：每轮文件变更摘要带 Undo；确认窗列出 可安全撤销/不可撤销/将被忽略 三类文件；不可撤销=未保存改前内容的文件、用户手改过的文件、终端命令引起的变更（走 Git 兜底）；撤销后可 Reapply。
5. 排队消息的编辑=整条（含附件）撤回输入框重新发送；`/compact` 等即时命令无编辑入口。

#### 4.1.20 闲时任务（FR-C-46）

**描述**：延迟可接受的一次性任务排队等闲时自动执行（如批量整理、长文档翻译、资料批量清洗）。**与 ZCode 的差异（明示）**：ZCode 闲时任务走服务端免费算力（其订阅经济学）；LaboFlow 为 BYOM/私有网关，闲时任务在本机闲时执行、消耗计入用户渠道或组织配额，无「免费」概念。

**交互与规则**：
1. 入口：自动化页「闲时任务」tab；表单（标题/指令/项目仅本地/权限默认「变更前确认」/模型与思考强度）。
2. **闲时条件**（本机判定，可配置）：无任何进行中的前台会话 且（可选）系统空闲 ≥N 分钟（默认 10）。
3. 队列：全局 FIFO、显示排队位次；排队中可编辑/暂停/删除；执行中可取消；暂停过久自动重新排队（位次靠后）。
4. 执行：后台运行不占前台；结果进新会话并在侧边栏「闲时任务」分组出现；用户插话排队至当前轮结束后发送（该轮正常计费）；失败不自动重试；每日创建上限（默认 5，可配，用尽显重置倒计时）。
5. 「保持唤醒」全局开关与定时任务共享；休眠暂停不丢任务，唤醒后重新排队。

#### 4.1.21 远程开发（FR-C-49，P4）

**描述**：把项目工作区迁移到远程主机（SSH）/WSL 发行版/Docker 容器：文件读写、命令执行、Git 与 Agent 运行时在目标环境执行，桌面端只保留账号、模型配置与 UI。

**交互与规则**：
1. 连接方式：SSH（内置客户端直连，读 `~/.ssh/config` 别名，默认端口 22，密码/私钥+passphrase，凭证加密存本地；**不支持 ProxyJump/ProxyCommand**，跳板需自行端口转发）、WSL（仅 Windows 桌面，慎用 root）、Docker（运行中容器，docker exec/cp）。
2. 远端安装 LaboFlow 运行时组件（`~/.laboflow/server`）；要求 POSIX shell（不支持原生 Windows 远程主机）；资源下发两种：本地下载后 SFTP 上传（远端可离线）/远端直连 CDN（需外网与校验工具）。
3. 连接向导：选择方式 → 填配置 → 连接中（实时日志与失败原因）→ 选择目录；失败可回退改配置。
4. **配置同步**：Skill/MCP/Plugin 三项、仅用户级、手动触发、跳过远端同名、部分失败不影响成功项；**MCP 密钥原样写入远端——仅同步到受信任主机（UI 强警示）**；Docker 不支持同步。
5. 仅本地项目可建定时/闲时任务的限制解除规则：远程工作区可查看已有任务但不可新建。

#### 4.1.22 Remote Control（FR-C-50，P4）

**描述**：把桌面端当前窗口临时暴露给手机浏览器：扫码/输 URL 后手机可查看与切换该窗口内的工作区/会话并继续下发指令。手机是纯控制层，指令实际执行位置由工作区类型决定（本机/SSH/WSL/Docker）。

**交互与规则**：
1. 桌面左下手机图标 → 弹窗（QR + 可复制 URL）；控制端为手机浏览器 Web 页，无需安装 App。
2. **URL 即完整临时授权**：任何持 URL 者可操作；**同时仅一个手机连接**；关闭弹窗不断连，必须点「停止」；怀疑泄露 → 刷新 QR 立即作废全部旧地址并强制重扫。
3. 手机可：按工作区/时间线浏览任务、排序、刷新、在已有工作区新建任务、触发远程工作区重连、会话页发指令、复制/点赞/点踩、条件性分叉；不可：新建远程连接、访问窗口外环境、管理自动化（移动端不显示自动化内容）。
4. 桌面必须在线；**中继方式**：登录组织时经 LaboFlow 服务器中继（WS，推荐，穿越 NAT）；未登录时仅限直连模式（同一局域网/可达地址），UI 明示局限。

#### 4.1.23 会话产物工作台（FR-C-51，P1，v1.2 新增）

**描述**：会话主视图从「纯消息流」升级为「过程时间线 + 产物」双轨（对标 Cortex 会话工作台形态）：思考节点、工具调用节点、子代理派发节点以紧凑卡片呈现在时间线上；Agent 产出的文件（PPT/文档/图表/网页）以**产物卡片**呈现，可预览、可追溯版本。

**交互与规则**：
1. 时间线节点：思考（灯泡图标 12px，可展开思考全文）、工具（默认一行摘要，展开输入/输出）、子代理（名称/状态/耗时/tokens）；节点间以细线连接，密度偏紧凑。
2. 产物卡片：类型图标、标题、版本号（v1/v2…）、生成时间；点击进预览（复用交付物预览器）；卡片操作：打开所在目录、加入交付物库（P2）、分屏对比（选两个版本左右对照，差异高亮）。
3. 会话产物落 `artifacts` 表并在右侧上下文面板「产物」分组汇总；会话导出（md/html）包含产物清单。
4. 版本语义：Agent 覆盖同名产物文件时自动生成新版本（旧版本快照留存，可回看）。

**异常与边界**：产物文件被用户手动删除 → 卡片标「文件缺失」保留元数据；分屏对比仅支持文本类与图片类（Office 类转文本后对比）。

#### 4.1.24 Slide 引擎（FR-C-52，P2，v1.2 新增）

**描述**：面向咨询交付的高频场景「一句话到 PPT 初稿」：用户输入主题/提供大纲或文档，Agent 产出结构化 slide 方案（逐页标题+要点+讲稿备注），经内置模板渲染为可翻页预览的演示稿，导出**可编辑 PPTX**（用户后续在 PowerPoint/Keynote 里精修）与 PDF/PNG/网页版。

**交互与规则**：
1. 入口：会话内 `$slides` 技能调用、新建任务时选「生成 PPT」模板、或从文档产物卡片「转为 PPT」。
2. 生成管线：理解输入 → 大纲方案卡（逐页：版式类型/标题/要点，用户可增删改页与改版式）→ 逐页渲染（HTML 模板）→ 预览翻页器。
3. 模板库：内置 ≥8 套基础模板（含咨询常用：标题页/议程/数据页/矩阵/瀑布/路线图版式）；组织可发布自有模板包（P2 组织资产，含公司 VI 色/Logo 位）。
4. 导出：PPTX（元素级可编辑：文本框/表格/图形，非整页截图）、PDF、PNG（逐页）、HTML（网页版演示）。
5. 与产物工作台联动：成品自动登记为产物卡片并入版本管理；可一键入交付物库。

**异常与边界**：模板缺失字体回退系统字体并提示；生成失败按页重试不整体作废；PPTX 兼容性目标 PowerPoint 2016+/Keynote（以 LibreOffice 转换抽检）。

#### 4.1.25 深度研究（FR-C-53，P2，v1.2 新增）

**描述**：把「行业研究/市场扫描/竞品盘点」做成一键任务：Agent 自动产出研究计划 → 并行多路检索（Web 检索 + 项目内资料 + 知识库）→ 交叉综合 → 结构化研究报告（含引用溯源）。执行过程实时可见、可中断、可追问补查。

**交互与规则**：
1. 入口：会话内 `/research <问题>` 或任务模板；可指定范围（仅项目资料 / 仅网络 / 两者）、深度（快速/标准/深入，控制检索轮次与并发）。
2. 过程面板：计划（子问题树）→ 各子问题检索进度卡（来源数/命中摘要）→ 综合中；全程可停止，已完成部分保留。
3. 产出：Markdown 报告（执行摘要/分章节/数据表/来源清单）；**每个事实性陈述带引用角标**，点击跳转来源（URL 或项目文件路径）；报告登记为产物。
4. 用量：进入用量统计（消耗显著，UI 预估提示）。

**异常与边界**：检索源全部失败 → 降级为「仅项目资料」并明示；网络依赖走代理设置（组织环境常见）；报告超长自动分卷。

#### 4.1.26 全局捕获三件套（FR-C-55，P3，v1.2 新增）

**描述**：不打开主窗口也能「接住」转瞬即逝的想法与快速问答（对标 Cortex 随手接住）：①双击 ⌘ 唤起快捷回复浮窗（针对当前应用的选中文本/输入框上下文）；②⌘⇧N 闪记（一句话笔记直接入项目收件箱）；③Spotlight 式全局浮框（快捷键呼出，输入问题或指令，走当前默认会话上下文）。

**交互与规则**：
1. 快捷回复：双击 ⌘（可改键/可关）→ 浮窗显示当前选中内容摘要 → 输入指令 → 后台会话执行（遵守权限模式，涉及写操作回主窗口审批）；结果以系统通知+浮窗回显。
2. 闪记：⌘⇧N → 单行输入 → 存入选定项目「闪记」分组（notes），可后续让 Agent 批量整理。
3. 全局浮框：热键呼出 → 与最近会话或指定专家对话；Esc 关闭不丢输入。
4. 授权：辅助功能权限引导（macOS）/前台应用范围确认（Windows）；浮窗会话的权限模式独立默认「变更前确认」。

**异常与边界**：权限未授予时功能引导开启但不阻塞其他功能；全屏应用（演示模式）中抑制浮窗。

#### 4.1.27 本地语音（FR-C-56，P3，v1.2 新增）

**描述**：面向「顾问边看材料边口述」与「访谈录音转写」两场景：①输入框听写（按住说话/点击开关，本地 ASR，中英，零上传）；②录音文件批量转写（mp3/m4a/wav → 带时间戳文稿，喂给 4.1.4 专家访谈纪要 Skill）；③回复 TTS 朗读（走 BYOM 语音协议，默认关）。

**交互与规则**：
1. 听写：输入框麦克风按钮；本地推理（sherpa-onnx 类运行时），首次使用下载模型（明示体积与路径，可拒绝）；识别文本落输入框可编辑。
2. 转写：文件拖入会话 →「转写为文稿」→ 产物卡片（带时间戳 md）；时长上限与分段策略可配。
3. TTS：设置→语音选择渠道与音色；仅对 Agent 最终回复朗读，流式过程不读。
4. 隐私红线：**语音音频零上传**（ASR 本地；TTS 仅合成文本出网，走用户配置渠道）。

**异常与边界**：模型未下载时听写/转写不可用（明示引导，可跳过）；长音频分段处理可中断续跑。

#### 4.1.28 Loop 可视化工作流（FR-C-57，P3，v1.2 新增）

**描述**：把「定时任务+人工审批+多步骤」编排为可视化节点流：画布上连接 触发器（定时/手动/事件）→ 会话步骤（绑定专家与权限模式）→ 条件分支 → **人工审批节点** → 推送节点（消息中心/邮件/IM）。运行时逐节点点亮显示执行轨迹。

**交互与规则**：
1. 画布：左节点面板 + 拖拽连线；节点参数抽屉；画布缩放/对齐；模板（晨会动态/周报汇编/风险扫描）预填。
2. 审批节点：运行到该节点暂停 → 消息中心/IM 推送审批卡 → 批准继续/拒绝走终止或备选分支；超时策略（等待/自动通过标记/自动拒绝）三选。
3. 与定时任务关系：Loop 是超集；定时任务可「升级为 Loop」；调度底座共用（Scheduler），配额与并发上限共用。
4. 运行历史：每次执行生成轨迹图（每节点状态/耗时/token），可回放展开各节点会话。

**异常与边界**：节点并发上限（默认 3）；循环防呆（最大迭代数，默认 10，可警示不可无限）；画布仅本地保存（组织下发为 P4+）。

#### 4.1.29 消息中心与推送（FR-C-58，P2，v1.2 新增）

**描述**：App 内统一消息收件箱：定时/闲时/Loop/深度研究等后台任务的状态与结果、审批请求、配额告警、组织公告，一处可查、可配推送。

**交互与规则**：
1. 侧栏铃铛入口 + 未读角标；列表按时间倒序，保留 60 天自动轮换；点击跳转对应会话/任务/审批卡。
2. 推送渠道：桌面通知（默认）、邮件（SMTP 配置，用于下班后长任务）、IM（P4 FR-S-16）；每任务可配渠道组合。
3. 分类与免打扰：任务/审批/告警/公告四类；勿扰时段（默认关）。
4. 审批类消息在通知上直接给「批准/拒绝」快捷操作（macOS 通知按钮）。

**异常与边界**：邮件配置失败降级仅站内+桌面通知；消息不含会话正文（仅摘要+跳转），降低泄露面。

#### 4.1.30 写作模式（FR-C-59，P3，v1.2 新增）

**描述**：长文档（咨询报告/方案书）专注写作视图：左大纲树（可拖拽调序）+ 中正文（Markdown，分节折叠）+ 右引用素材栏（会话产物/研究引用/资料卡片）；Agent 可按节润色/扩写（选中段落 → 指令浮条）。

**交互与规则**：
1. 从产物（md）或会话「转为写作模式」进入；全屏专注布局，退出回会话。
2. 引用素材：从产物卡片/研究报告拖入素材栏；插入为引用块（保留来源）。
3. Agent 协作：选中文字浮条（润色/扩写/改语气/查证）；修改以 diff 呈现确认后落稿。
4. 成稿：导出 md/docx（模板套用公司样式，P2 组织资产）入交付物库。

**异常与边界**：单文档建议 ≤5 万字（超限提示拆卷）；协作修改均经确认，不静默改稿。

#### 4.1.31 媒体生成（FR-C-60，P3，v1.2 新增）

**描述**：BYOM 式媒体生成配置：图片（openai-images 兼容协议）、语音（openai-speech 兼容）、音乐/视频（协议适配器扩展位）。产出供 Slide 引擎配图、写作模式插图与会话引用。

**交互与规则**：
1. 设置→媒体生成：四类各自 启用开关/渠道（复用渠道体系或独立 BaseUrl+Key）/默认模型与参数（分辨率/音色/时长）。
2. 会话内 `/image`、`/tts` 等命令与 Slide 引擎自动调用；产出登记产物卡片。
3. 用量进入统计（按渠道计费口径）。
4. 默认全部关闭；未配置时相关入口隐藏不报错。

**异常与边界**：生成超时/失败给重试；内容安全责任由上游渠道承担并在设置页明示。

### 4.2 服务端（LaboFlow Server + Admin Console）

#### 4.2.1 账户与认证（FR-S-01）

1. 账号仅由系统管理员（或授权团队管理员在其团队内）创建：用户名、显示名、初始密码（生成后一次性展示）、所属团队、角色。无自助注册、无邮箱验证流程。
2. 首次登录强制改密（must_change_password）；支持管理员重置密码（重置后再次强制改密）。
3. 认证：JWT（access 30min + refresh 14d）；支持单设备多会话；管理员可强制下线用户。
4. 密码存储：argon2id；失败锁定（5 次失败锁 15 分钟）。

#### 4.2.2 组织角色与团队管理（FR-S-02/03）

**角色与权限矩阵**（单租户：一次部署 = 一个组织）：

| 能力 | 系统管理员 | 团队管理员 | 普通用户 |
|---|---|---|---|
| 团队 CRUD、指定/改任团队管理员 | ✅ | ❌（仅管理本团队用户） | ❌ |
| 本团队内用户增删改、重置密码 | ✅ | ✅（不可管理团队管理员本人；不可增删管理员） | ❌ |
| 工作区创建/删除 | ✅ | ✅（限本团队） | ❌ |
| 工作区成员与权限配置 | ✅ | ✅（限本团队工作区） | Manager 见 4.1.13 |
| 模型上游渠道管理 | ✅ | ❌ | ❌ |
| 配额策略：系统级全局 | ✅ | ❌ | ❌ |
| 配额策略：本团队 | ✅ | ✅（不得宽于系统级） | ❌ |
| 组织 Skill/专家库发布 | ✅ | ✅ | ❌ |
| 审计日志查看 | ✅ 全部 | 本团队 | ❌ |
| 使用产品功能（会话/工作区参与） | ✅ | ✅ | ✅ |

**规则**：每团队默认仅 1 名团队管理员（由系统管理员指定/改任）；团队管理员不可自我提升；删除团队需先转移或删除其用户与工作区。

#### 4.2.3 模型接入与中转网关（FR-S-04/05/06）

1. **上游渠道**：系统管理员配置上游（供应商类型：OpenAI 兼容/Anthropic/Gemini；BaseUrl；真实 API Key（加密存储）；启用的模型与显示名、单价（用于成本核算，可留空）；备注）。支持多上游并存（如同模型多供应商容灾）。
2. **分配**：渠道可分配给「全部 / 指定团队 / 指定用户」。
3. **中转**：网关对外暴露 OpenAI Chat Completions 与 Anthropic Messages 两种协议端点；客户端虚拟 Key 鉴权 → 鉴权通过后按映射转发上游，流式透传（SSE），不落盘对话内容（仅计量元数据）。
4. **虚拟 Key**：登录后自动签发（长随机串，绑定用户）；可吊销重发；Key 中不含任何上游真实凭据。
5. **计量**：每次调用记录（用户、团队、模型、输入/输出 tokens、时间戳、延迟、上游状态码）；响应头回传本次用量（兼容两种协议的 usage 字段）。
6. **健康**：上游探活；失败率超阈值标记降级；管理台可视。

#### 4.2.4 用量控制（配额）（FR-S-07/08）

1. **限额维度**：会话数（新建会话计数）与 Token 用量（输入+输出），可单选或组合（任一触顶即限制，即「先触及先生效」）。
2. **周期**：每日 / 每周 / 每月（自然日历，时区取服务器配置），可单周期或组合限制。
3. **层级**：系统管理员设全局配额（作用于全体或指定团队）；团队管理员设本团队配额。**冲突时从严者生效**（系统级约束是下限，团队只能更严或相等，UI 中联动提示）。
4. **对象**：配额按「团队」或「用户」设置（二选一粒度，团队级为默认）。
5. **触顶行为**：网关拒绝新调用（返回明确错误码与配额信息）→ 客户端提示「配额已用尽，将于 X 时间重置，可切换个人渠道」；已进行中的流式响应不截断（在开始时检查）。
6. **余量与告警**：余量查询 API；阈值告警（默认 80%/95%），管理台站内信 + 可选 Webhook。

#### 4.2.5 共享工作区服务（FR-S-09/10）

1. 工作区：名称、描述、所属团队、成员列表（用户 × 权限三级）、配额归属。
2. 共享会话存储：会话元数据 + 消息/工具轨迹条目（JSONL 条目化存储）；**回合制锁**：发言即加锁（用户+时间戳），Agent 空闲或 90s 无心跳释放；锁队列（排队发言）。
3. **WS 推流**：工作区/会话级频道，推送新条目、状态变更、成员在线列表；断线增量同步（按条目序号）。
4. 交付物库：文件元数据 + 对象存储（本地卷），版本历史（默认保留 20 版）；大小上限（默认单文件 200MB，可配）；预览服务（PDF/Office 转换预览）。
5. Agent 写入交付物：客户端经 REST 上传并关联会话条目。

#### 4.2.6 组织资源库（FR-S-11）

组织 Skill 库（P2）：团队管理员发布 Skill 包（含版本、说明、适用范围）；下发清单接口；客户端登录拉取后只读安装。组织专家库（P3）同机制。

#### 4.2.7 Web 管理控制台（FR-S-12）

页面与功能：仪表盘（组织用量趋势/活跃用户/配额告警汇总）、用户管理、团队管理、工作区管理（列表/存储用量）、模型渠道管理、配额管理（策略编辑器 + 余量视图）、组织资产库（Skill/专家）、审计日志（筛选/导出）、系统设置（服务器时区、告警 Webhook、备份）。管理员首次使用引导（三步：建团队 → 建用户 → 接模型）。

#### 4.2.8 部署与 SSL（FR-S-13）

1. 交付物：docker-compose.yml + .env 模板 + 部署文档；组件：api（NestJS）、web-console（静态）、postgres、caddy（反代 + TLS）。
2. SSL：集成 acme.sh，域名与邮箱配置后自动申请/部署/续期（Let's Encrypt）；HTTP 自动跳转 HTTPS；也支持自带证书模式。
3. 升级：新版本镜像 + 自动数据库迁移脚本；备份：每日 pg_dump + 交付物卷快照（保留策略可配）。
4. 硬件基线：2C4G 起步（≤50 用户），4C8G 推荐。

#### 4.2.9 审计日志（FR-S-14）

记录：登录/登出/改密、用户与团队管理操作、渠道与配额变更、工作区与权限变更、网关调用元数据（谁/何时/何模型/多少 tokens，不含内容）、Skill 库发布。保留策略可配（默认 180 天），仅系统管理员可配置导出。

#### 4.2.10 Bot Channel（FR-S-16，P4）

**描述**：把 IM 接入 LaboFlow：在飞书/企业微信/钉钉的会话里打开工作区、查看任务进度、继续下发指令——IM 成为长期回访入口（与 Remote Control 的「临时接管」互补）。

**交互与规则**：
1. 支持顺序：飞书/Lark → 企业微信 → 钉钉（面向咨询团队主流 IM；微信个人号合规风险高列为可选）。自建应用方式接入（企业自有开放平台应用），凭证由企业管理员在客户端配置。
2. 绑定：飞书用限时绑定命令（如 `/bind C67356`）；绑定后可用命令：查看状态/新建任务/切换项目/切换模型/切换执行模式/调整回复详细程度。
3. 回复粒度三档（标准/完整/摘要，按 bot 配置）；**飞书流式卡片**：Agent 回答在单张卡片原地更新，工具段折叠摘要；需要用户决策（选方案/授权/确认计划）时当前卡片冻结、另发新卡提问，回复后新卡继续。
4. Bot 管理：链接/解绑、回复粒度、**工作区访问范围限制**（限定 bot 可见工作区）、启停、连通状态、删除。
5. 服务端职责：IM webhook 回调接收与签名校验、消息路由至对应桌面端（经 WS 推送）、出站消息回传；全程 TLS，回调验签防伪造。

| 合规 | 数据不出组织边界（私有化部署）；用户数据删除（管理员删除用户即级联删除其共享内容，本地缓存 TTL 清理） |

## 6. 数据埋点与指标

客户端埋点**默认关闭**（隐私优先）；组织部署的管理台指标基于服务端计量与审计数据（非客户端埋点），默认可用。客户端可选开启匿名产品改进遥测（事件：app 启动/会话创建/工具调用计数/Skill 使用/崩溃；不含任何内容与凭据）。核心指标看板见 1.4；指标定义：

| 指标 | 定义 |
|---|---|
| 周活跃会话数 | 自然周内由去重登录用户发起的会话数（组织维度汇总） |
| 会话完成率 | 会话中产生 ≥1 条用户满意的结束信号（导出/点赞/无立即重试的报错）占比 |
| 网关用量可见率 | 走网关调用的 tokens / 组织总 tokens |
| 配额触顶率 | 触顶人日 / 活跃人日 |

## 附录 C：UI/UX 对齐规范（ZCode/Codex 复刻基准）

**设计目标**：让 ZCode/Codex 用户零学习成本迁移。对齐策略=**交互与视觉惯例的全面复刻 + 品牌资产自立**：布局结构、信息架构、快捷键、色彩语义、组件形态与 ZCode/Codex 惯例逐项对齐（来源：官方公开文档描述 + 行业共识形态）；LaboFlow 自有 logo、图标集与文案（不复制对方品牌资产，避免混淆与商标问题）。

**C1 布局（三栏，均可折叠/快捷键切换）**：左侧任务侧栏（工作区/任务列表 + 底部功能入口：自动化/用量/设置/账号）；中部会话主区（消息流 + 输入区）；右侧上下文面板（计划/todo/goal card/子Agent/浏览器/预览）。右侧面板顶部「+」= 辅助对话等入口。
**C2 输入区元素排布**：左下「+」（附件/@/#//）；右下依次 思考强度图标（⌃T）、模型名（⌃M）、执行模式选择器（⇧Tab 循环，色彩编码 琥珀/蓝/紫/红）；发送按钮。
**C3 任务侧栏**：三视图（分组 7 色/工作区/时间线）+ 排序 + 搜索 + 归档入口；任务行=标题 + 相对时间 + 状态点（运行中/未读/失败）+ `+/-` 变更行数；免项目会话与项目会话并列。
**C4 命令面板**：`/` 面板（命令/技能两分组、↑↓ 导航、Enter/Tab 确认、Esc 关闭）；命令中心 ⌘K（命令/会话/文件三域搜索 + 快捷操作）。
**C5 快捷键表（与 ZCode 键位一致）**：

**C6 会话内渲染**：Markdown + Mermaid 成图（缩放/平移/Esc）+ KaTeX + Shiki 代码高亮；图片预览/图集；表格工具栏（复制/下载 CSV/大预览/宽表横滚）；diff 双模式；PDF 只读预览。
**C7 状态可见性**：权限审批卡与计划门内联不打断；goal card 与迭代 checklist 常驻右栏；todo 进度条；任务状态点；用量角标。
**C8 视觉语言**：亮/暗/自动主题；中性灰基底 + 单一低饱和强调色；语义色=模式色彩编码与状态色；密度适中偏紧凑；卡片圆角 8–12px；等宽字体用于代码与工具输出。
**C9 明确不复刻项**：ZCode/Codex 的 logo、图标素材、产品名与营销文案；像素级抓取对方资源不在方案内（以公开文档描述的行为与布局惯例为对齐基准）。

**C10 双基准冲突裁决表（v1.2 新增，ZCode × Cortex）**：ZCode 与 Cortex 是两种设计语言（ZCode：冷中性灰 + 低饱和强调色的编码工作台；Cortex：暖中性灰 + 黑白无彩强调 + 玻璃层的产物工作台）。「同时像素级复刻两者」在两者冲突处不可达，按下表裁决（**本文档的裁决即为验收基准**）：

| UI 维度 | 基准来源 | 裁决理由 |
|---|---|---|
| 信息架构 / 布局骨架（三栏、任务侧栏三视图、输入区元素排布、命令面板、右栏面板组） | **ZCode** | LaboFlow 主体语义（项目/会话/权限四档/快捷键）全面对齐 ZCode，用户迁移成本最低；附录 C1–C7 不变 |
| 会话流节点形态（时间线节点：思考/工具/子代理卡片、产物卡片、版本、分屏对比） | **Cortex** | Cortex 的过程时间线+产物双轨对「交付物可见性」更强的咨询场景是明确增量；ZCode 此处偏开发者向 |
| 色板 / 表面色 / 文字色（全部 bg/border/text/accent token 值） | **Cortex 实测值**（附录 D-D1/D2） | 暖中性灰 + 黑白强调更克制高级，即本轮 UI 升级的核心诉求；LaboFlow 现行蓝灰+teal 体系废弃 |
| 语义色（权限四档模式色、状态色、图表配色） | **ZCode** | 权限模式色彩编码（琥珀/蓝/紫/红）是行为语义的一部分，与 4.1.3 绑定，保留 |
| 图标 | **自有化 lucide 体系**（16px 线性描边、stroke 2） | 两家图标形制相同（16px 线性）；lucide-react（MIT）覆盖两家全部语义；**不拷贝任何一方图标资产**（D4） |
| 字体 / 度量（系统字体栈、4px 间距基数、4/6/8/12/16 圆角、150ms 过渡） | **Cortex 实测值** | 与色板同源，成体系采纳 |
| 侧栏与玻璃层（256px 侧栏、backdrop-blur 玻璃顶栏） | **Cortex 实测值** | 视觉高级感的主要来源之一；玻璃层在低端机可关（性能开关） |
| 快捷键 / 面板行为 / 动效时序 | **ZCode** | 附录 C4/C5 键位表不变；面板开合动效 150ms 对齐 Cortex 度量 |
| 设置中心 / 管理台 / 移动 Web 控制页 | **ZCode 布局 + Cortex 视觉 token** | 结构跟 ZCode，皮跟 Cortex |

### D3 度量、字体与图标规范

- **间距**：基数 4px（Tailwind 默认刻度）；侧栏宽 256px（w-64，展开 288px/w-72，可折叠至图标栏 48px）
- **圆角**：chip/输入框 6px；卡片 8px；弹窗/浮层 12px；大容器 16px
- **过渡**：150ms `cubic-bezier(.4,0,.2,1)`（面板开合、hover、抽屉）
- **字体**：`ui-sans-serif, system-ui` 系统栈（不引入自定义字体，与 Cortex 一致；等宽 `ui-monospace/SFMono` 用于代码与工具输出）；正文 14px/1.375、辅助 12px/1.4、时间线节点标签 11px
- **图标（自有化规范）**：lucide-react 为基础库（MIT），按以下规则**收敛为一套 LaboFlow 图标层**（`packages/ui/icons` 统一导出，禁止业务代码直引 lucide）：
  1. 默认尺寸 16px（导航/工具栏/按钮内）、12px（时间线节点/角标）、20px（设置分组头）；stroke-width 2（「更多」类 2.4）
  2. lucide 缺失或形制不合的（如权限四档徽标、产物类型角标），以同形制自绘 SVG 补齐（描边圆头、2px、24 网格缩放）
  3. **禁止**：emoji 占位（U 冲刺验收清零）、从 ZCode/Cortex 提取任何图标资源
- **投影/玻璃**：浮层用 `backdrop-blur(12px)` + 52% 透明表面色；阴影仅用于浮层（卡片靠表面色分层，不加投影）——Cortex 分层法的核心
- **空态/加载**：空态=图标 20px+一行主文案+一行辅助文案+一个动作按钮；加载=12px spinner 或骨架屏（卡片类）；流式生成中=光标闪烁

### D4 合规红线（资产边界）

1. 不拷贝、不反编译还原 ZCode/Cortex 的图标、logo、插画、字体、音效、动效文件与文案字符串。
2. 视觉对齐的定义 = **布局结构、token 数值、组件形制、交互时序**的规格对齐（思想与功能规格，不受版权保护），以自建代码与自有资产实现。
3. 对外宣传与商店素材不得使用两家产品的截图做对比。
4. 逆向所得 Cortex 源码仅存于调研者本机（/tmp），不进入仓库、不进入 issue/文档附件。

### D5 验收机制（截图基线库）

1. `docs/design/baseline/` 存双基准截图（ZCode 与 Cortex 各 8 屏：工作台/会话/审批卡/命令面板/设置/市场/任务视图/暗色模式），每屏配区域标注（区域名/期望 token）。
2. LaboFlow 同屏截图入 `docs/design/current/`，逐区域比对清单（区域尺寸差 ≤4px、色值差 ≤2%（ΔE≈3）、图标形制一致、间距基数一致）。
3. U 冲刺与后续每个 Gate 跑一次全量比对，通过率 ≥90% 方可过关；未过项登记跟踪。
4. 盲测：5 名顾问对升级前后界面「专业度/易读性/高级感」1–5 分，均值 ≥4 分。
