# LaboFlow 阶段性验收计划（PRD/PLAN/SPEC 对照 + Computer-Use 视觉实测）

- 日期：2026-09-07
- 验收范围：PRD v1.2 / PLAN v1.3 / SPEC v1.2 交付的功能模块 + UI/UX 像素级对齐（ZCode/Codex 基准）
- 验收人：agent（自主验收），结果供用户复核

---

## 一、验收目标

1. **需求完成度**：PRD/PLAN/SPEC 列明的各功能模块均已实现（重点核查近期新增：Goal/Memory/Wiki/Research/Slide/通知/Composer 触发器/归档/Clawhub/思考接线/自动化深链）。
2. **功能真实性**：排除"安慰剂"——每个按钮/入口必须有**真实的后端响应**（数据变化、IPC 调用链闭合、服务层逻辑执行），前端不能只做了 UI 壳。
3. **UI/UX 对齐**：三卡圆角+阴影布局、Token v3 配色、单橙权限语义、卡片式设置行、字号档位——像素级比对 ZCode 参考图。

## 二、验收方式

| 方式 | 工具 | 覆盖 |
|---|---|---|
| A 自动化门禁 | pnpm test/lint/typecheck/build + E2E 脚本 | 回归保障 |
| B Computer-Use UI 实检 | macOS screencapture + a11y 树 + 坐标点击 | 运行实例的真实视觉与交互 |
| C 安慰剂审查 | 每按钮点击后验证：(1) 状态变化；(2) 数据落盘（SQLite/文件）；(3) IPC 链路日志 | 排除假按钮 |
| D 像素级比对 | Token v3 基准测试 + 截图对照 ZCode 参考图 | 布局/配色/字号 |
| E 代码审计 | grep 关键接线（安慰剂检查的静态面） | 后端真实性 |

## 三、通过标志

- A：test 全绿（≥313）+ lint 0 error + typecheck 五包 + build + E2E PASS
- B：9 个 UI 检查点全部有截图证据且**状态真实变化**
- C：全部按钮点击后可追溯到后端调用/数据变化，零"纯 UI"死按钮
- D：Token v3 基准测试 6/6 + 三卡布局截图与 ZCode 结构一致
