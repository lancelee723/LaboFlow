## 一、验收过程中发现并修复的缺陷（本报告最重要的产出）

| # | 缺陷 | 严重度 | 根因 | 修复 | 回归验证 |
|---|---|---|---|---|---|
| 1 | **统一触发器整体失效**：真实输入 `@`、`#`、`/` 均不弹出任何弹窗 | 高（安慰剂） | T2.9 将 textarea 抽成 `Composer` 组件后，弹窗触发逻辑仍留在 `ChatView`，依赖的 `input` 状态永远为空串；`#` 会话引用 effect 在重写中丢失；`/` 的 `slashOptions` 只赋值从未渲染 | 三种触发器整体迁入 `Composer`（它才是持有输入文本的组件），`/` 弹窗补齐渲染与插入逻辑，`#` 会话引用 effect 恢复 | 实机验证：键盘输入 `/` → 弹窗出现（截图 ac02e）→ 点击 `/goal` → 输入框变为 `/goal `（截图 ac02g） |
| 2 | `/` 弹窗点击命令项后**文本不替换**（弹窗关闭但输入框仍是 `/`） | 高 | 新增 `insertPopupItem` 缺少 `/` 前缀分支，`/goal` 落入 `@` 替换分支导致替换不生效 | 补 `/` 分支（`prev.replace(/\/([^\s/]*)$/, f.path))` | 同上实机复测通过 |
| 3 | 设置→模型设置页出现**裸 i18n 键名**（"+ models.addProvider"、"models.configured"） | 中 | zh-CN/en 语言包 `models` 块缺少这两个键 | 两个语言包补齐 `configured`（含 `{{n}}` 插值）与 `addProvider` | 实机复验：显示「已配置模型 0」「＋ 添加供应商」（截图 set-models3） |
| 4 | `ChatView` 死代码（`input` 状态、死 `submit`、旧 `insertMention`/`insertSlash`、模块级 `slashPopupOpen`） | 低 | 与 #1 同源的重构残留 | 一并清除；`typecheck`/`lint` 归零 | lint 0 / typecheck 0 |

> 说明：#1 属于上一轮"Composer 抽取 + W1 统一触发器"两个改动叠加后的**集成回归**，此前的组件级测试均绿但未覆盖"真实输入 → 弹窗出现"的完整链路——这正是本次"自主验收 + 实机操作"设计要抓的问题类别。

## 三、已确认完成的功能（本轮实机复核 + 门禁）

1. **会话核心链路**：新建/发送/流式回复/工具调用卡/系统消息/token 计数（mock 引擎端到端）。
2. **统一触发器**：`@` 文件、`#` 会话、`/` 命令、`$` 技能、＋菜单四入口（本轮修复后达到可交付状态）。
3. **思考档位**：UI 四档 → `sessions.thinking` 落库 → 每轮传引擎（此前已接真，本轮复核）。
4. **权限模式**：单橙胶囊语义、确认/自动编辑/计划/完全访问循环（EngineHost 门禁链路有契约测试）。
5. **归档闭环**：行 hover → 归档 → 列表移除 → 归档记录页可见（恢复/删除服务层有单测）。
6. **设置中心**：20 个分区齐全，顺序符合要求（个人资料第一、记忆管理在权限下、归档在用量上）；主题/字号即时生效且持久化。
7. **Goal 命令**：`/goal` 拦截 → GoalService → 系统消息 + 落库 + 计数。
8. **模型管理**：默认模型双下拉、分组 tab、添加供应商通道。
9. **Clawhub 在线技能**：tab 与搜索入口真实（真实网络搜索属外部依赖）。
10. **工程底座**：EngineHost worker、Artifact 版本链、Hooks、Goal/Memory/Wiki/Research/Slide/通知服务、自动化、远程开发/RC/Bot（P4 已验收）——297 项测试全绿。
