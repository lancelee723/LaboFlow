## 一、P1 收尾（先于 P2，按 PLAN 顺序）

### T1.15 agent-browser 执行器插槽 ✅（ADR-15，5 单测）
- `agent-browser-executor.ts`：二进制探测（env 覆盖 > 打包资源 > dev 路径）+ `--version` 探活（spawnSync 带超时）+ 常驻子进程 JSON-lines 协议适配（ping/navigate/eval/screenshot/close）。

## 二、P2 服务端批次（T2.1–T2.5）

### T2.1 服务端骨架与部署链 ✅
- **技术栈落地**：NestJS 11 + Fastify adapter + **Drizzle ORM**（SPEC §2 授权的「Prisma 或 Drizzle 实现期定一」——选 Drizzle：无 codegen、类型直推、依赖轻）+ pg。
- **幂等迁移器**（镜像桌面端模式）：`schema_migrations` 版本表 + 编号迁移列表；P2 核心八表（teams/users/provider_channels/virtual_keys/quota_policies/quota_counters/usage_logs/audit_logs）。
- **bootstrap()**：一键起 API（连库 → 迁移 → Nest 模块 → listen）；`/healthz` 报 P2-beta。
- **部署交付物**：`deploy/docker-compose.yml`（postgres 16 + api + caddy，健康检查/数据卷/备份卷）、`Caddyfile`（ACME 自动证书 + HSTS，自带证书模式注释位）、`.env.template`、`apps/server/Dockerfile`（node22-alpine 三段构建）。
- 认证实现选型说明：AuthGuard（Nest APP_GUARD 惯用法）替代初版 fastify addHook（时机脆弱）；公共路由（healthz/login/gateway）显式标记——gateway 用**虚拟 Key 自认证**，不走 JWT。

### T2.2 认证与账户 ✅（集成测试全链路）
- **argon2id**（@node-rs/argon2 预编译二进制，无 node-gyp 风险）；强度校验（≥10 位含字母数字，违者 422）。
- **JWT 双令牌**：access 30min + refresh 14d（jose HS256）；AuthGuard 校验并注入 actor。
- **失败锁定**：连续 5 次失败锁 15 分钟（计数器 + locked_until，成功登录清零）。
- **首登强制改密**：must_change_password 标志 → change-password 通路 → 标志清除 + 重发令牌 → 重登录验证为 false。
- **管理员重置密码**：canManageUser 层级校验（member 永远无管理权；team_admin 只管本团队 member；低级不可管高级）→ 重置后再次强制改密。
- **审计**（FR-S-14 切片）：login.ok / login.fail / login.locked / password.change / user.create / team.create / vkey.issue 全部落 audit_logs（追加写）。

### T2.3 RBAC 与团队管理 ✅（矩阵单测 6 组 + 集成 403 矩阵）
- `rbac.ts`：PRD 4.2.2 矩阵纯函数化——团队 CRUD/指定管理员（仅系统管理员）、本团队用户管理（team_admin 限本团队且不可动管理员）、工作区（team_admin 限本团队）、渠道/系统级配额（仅系统管理员）、团队级配额（本团队管理员）、组织资产发布、审计视图分级。
- 集成验证：member 建用户/建团队 403；team_admin 建团队/动系统配额 403、设本团队配额 200。
- **唯一团队管理员约束**：第二个 team_admin → 409（应用层守卫 + teams.admin_user_id 反写）。

### T2.4 Model Gateway ✅（注入式 mock 上游，双协议计量断言）
- 管线：虚拟 Key 鉴权（sha256 查库，吊销即拒 401）→ 配额预检 → 路由（模型匹配 + assign 范围过滤 + 健康度排序）→ 上游代理 → **usage 解析计量**（ADR-6：服务端解析为准）→ usage_logs 落库。
- **双协议**：`/gateway/openai/v1/chat/completions`（prompt/completion_tokens）与 `/gateway/anthropic/v1/messages`（input/output_tokens）各自断言 usage 提取正确。
- 计量断言（真实 PG 查表）：usage_logs 行（model/status/tokens）正确；**quota_counters 原子累加**（100+42 → 再 100 → 200，UPSERT ON CONFLICT DO UPDATE）。
- 虚拟 Key 签发/吊销：明文只在签发瞬间，库中仅 sha256；无效 Key 401；未知模型 404。
- 上游 fetch 可注入（测试零外网）；真实网络流式透传（SSE pipe）随 T2.6 客户端对接一并压测（k6 外部项）。

### T2.5 配额引擎 ✅（纯逻辑 13 单测 + 集成 429 链路）
- **取严合并**：system 全局 ∪ system-团队 ∪ team 策略 → 每 (kind × period) 取 min；他队策略不可见。
- **先触及先生效**：sessions/tokens 任一触顶即限；tokens = in+out 合并计。
- **自然日历周期键**：daily/monthly/ISO weekly；Reset-After 精确到周期滚动（跨月末边界用例）。
- **团队级不得宽于系统级**：纯函数校验（宽松 → 拒绝）+ API 层 422 集成断言；等值/更严通过。
- **集成 429 链路**：system 250 tokens 策略 → 现有 200 → 下一次调用（+142）→ **429 + `Reset-After` + `X-Quota-Limit/Used` 头**，body code=EQUOTA。
- BYOM 语义：无策略不限；无团队归属（个人 Key）不占组织配额。
