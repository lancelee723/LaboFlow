## 1. 背景与定位

### 1.1 业务背景

咨询团队的项目协作现状：材料散落在微信/邮件/网盘，Agent 产物靠截图复制，评审靠批注邮件往返。用户需要**人和 Agent 在同一份材料上工作**：权限决定谁能看、也决定 Agent 能用什么。

对标 Workbuddy「资料库·团队空间」；其 MD 文档的「划词评论 + AI 修订建议（接受后生效）」审阅模式是本模块的核心体验。调研确认：Workbuddy 的「人机双写」（Cowriting，腾讯文档驱动）是**选区指令式原地修改**（高亮 + 撤销），并无修订建议 accept/reject 流——本模块做同款「建议-审阅」制，在桌面端自有文档栈上实现。

### 1.2 产品定位

团队空间 = 组织内的**资料库**：一棵可嵌套的文档树 + 四档成员权限 + 三种文档形态各司其职——

- **MD 文档**：纪要、方案、研究笔记。审阅模式：划词评论 + AI 修订建议（不覆盖原文，接受后生效）。
- **CSV 表格**：清单、排期、数据维护。轻量编辑 + Agent 读写。
- **HTML 文档**：视觉化页面（数据大屏、页面原型）。划词直接改 + 多人同时编辑。
- **文件**：PDF/Office/图片等上传件，预览与下载。

「数据与视觉分离」：结构化数据放 CSV，视觉呈现放 HTML/导出物。

### 1.3 权限与 Agent 的关系（本模块的灵魂）

> 权限不只决定谁能看，也决定 Agent 能用什么。把空间或文档带入任务后，Agent 只读取**当前用户有权访问**的内容——人看不到的，Agent 也读不到。不必为 Agent 单独维护一套权限。

Agent 对空间的所有读写以发起用户的身份经服务端执行（权限继承），且 Agent 的**修改**默认走修订建议（MD）而非直接覆盖。

## 2. 用户与场景

### 2.1 核心用户故事

- US-TC01 作为项目经理，我想为「某客户市场进入项目」建一个团队空间，嵌套组织文档树（行业研究/数据/交付稿），邀团队加入并分派权限。
- US-TC02 作为顾问，我想往空间放资料：新建 MD 写访谈纪要、上传客户给的 PDF、剪藏一篇行业文章网页、让 Agent 把生成结果直接落到空间里。
- US-TC03 作为顾问，我在 MD 里划选一段，@同事评论；同事回复形成讨论线程；我用「按评论修订」让 AI 读懂全部评论自动产出修订建议。
- US-TC04 作为项目经理，我划选一段让 AI 改写——AI 不直接覆盖原文，而是给出「原文/改后」对照的修订建议；我逐条或批量接受后才写入正文。
- US-TC05 作为顾问，我和同事同时编辑一份 HTML 数据页，各自的光标可见、互不踩踏；MD 则在审阅模式下协作。
- US-TC06 作为系统管理员，我想控制协作范围：仅允许组织内协作时，组织外账号无法通过链接加入。
- US-TC07 作为顾问，我把空间里的客户资料带给 Agent 做分析——Agent 只能读我有权限的内容；它对 MD 的修改以修订建议呈现，由我审阅。

## 3. 功能需求

优先级：M / S / C（C 为首批裁剪对象）。

### 3.1 团队空间与文档树

- **FR-TC-01（M）** 资料库左栏「团队空间」区列出我所在的空间；标题右侧 **+** 新建空间（用于一个项目/小组/业务线）；空间内文档树支持文件夹嵌套、拖拽移动、重命名、删除（进回收站，30 天保留）。
- **FR-TC-02（M）** 放入资料四方式：① 新建 MD 文档 / CSV 表格 / HTML 文档；② 上传本地文件（PDF/Office/图片等，单文件 ≤200MB 沿用交付物约束）；③ 剪藏网页链接（抓取正文转 MD/HTML 存档，附原 URL 与抓取时间）；④ **Agent 生成直落**——任务中指定输出到某空间，产物即刻落进空间无需二次搬运。
- **FR-TC-03（M）** 文档列表视图：树形 + 最近更新排序；条目显示类型图标/更新者/更新时间/评论数/待审修订数徽标。

### 3.2 成员与权限

- **FR-TC-04（M）** 权限四档（映射并扩展现有 viewer/contributor/manager）：

| 档位 | 可做的事 |
|---|---|
| 查看（viewer） | 浏览空间内容，不能修改 |
| 编辑（contributor） | 在空间内新建、修改和整理内容 |
| 管理（manager） | 管理空间成员与权限设置 |
| 无权限（none） | 不可访问该空间（不在列表出现，链接访问被拒） |

- **FR-TC-05（M）** 邀请与管理：空间菜单「邀请和管理成员」打开分享面板——当前成员列表（改档/移除）、**复制链接**邀请、二维码、微信等渠道分享；通过链接者可单独设定访问方式（需申请权限 / 可查看）。
- **FR-TC-06（M）** 协作范围管控（组织版）：企业管理员配置「允许组织外协作 / 仅组织内协作」；仅组织内时分享范围锁定组织内，组织外账号无法经链接加入。空间默认不公开；主动开启对外发布时范围由空间管理者掌握。
- **FR-TC-07（M）** **Agent 按同一权限读取**：任务中引用空间/文档时，Agent 的读取经服务端以当前用户身份过滤；Agent 试图访问无权内容时得到明确的权限错误而非空结果。

### 3.3 MD 文档审阅模式（核心体验）

- **FR-TC-08（M）** **划词评论**：选中文本→评论；评论锚定原文位置（侧栏与正文一一对应）；每条评论是讨论线程（多轮回复、@提及、状态流转：打开→已解决）；锚定失效（原文被改）时显示「位置已变化」并保留评论内容。
- **FR-TC-09（M）** **AI 修订建议**：划词选中并提出修改要求后，AI **不直接覆盖原文**——产出独立修订建议：
  - 待确认状态标注于原文旁（高亮 + 角标）；
  - 会话/侧栏列出「原文 / 改后」对照与**修改理由**；
  - 逐条**接受**（写入正文）/ **拒绝**（丢弃），或一次性全部接受；
  - 只有接受后才写入正文；多处修订互不干扰（应用时按锚定位置串行合并，冲突时提示重审）。
- **FR-TC-10（M）** **按评论修订**：一键让 AI 读懂全部评论与正文上下文，自动产出修订建议集（AI 只产建议，人只管审阅）；完成后可通知评论者复核（消息中心 + IM 推送，联动模块 03/04）。
- **FR-TC-11（M）** **AI 编辑可撤销**：AI 的每次写入（接受的修订/直接改）与用户手动编辑统一进撤销栈，逐步撤销/重做。

### 3.4 HTML 文档协同

- **FR-TC-12（M）** HTML 文档：所见所得编辑器（标题/段落/列表/表格/图片/嵌入图表块）；**划词直接改**（AI 指令就地应用，改动高亮，可撤销）。
- **FR-TC-13（M）** **多人同时编辑**：CRDT 实时同步（无锁合并），在线成员光标/选区可见（presence），离线编辑重连自动合并。
- **FR-TC-14（S）** HTML 预览模式（只读渲染）与编辑模式切换；导出为独立 HTML 文件。

### 3.5 CSV 表格

- **FR-TC-15（M）** CSV：类表格编辑（单元格编辑/增删行列/排序/筛选/类型提示），UTF-8 严格往返（不丢列/不改编码）；Agent 读写 CSV 作为任务上下文。
- **FR-TC-16（C）** CSV → 简单图表（柱/折线/饼）内嵌预览。

### 3.6 Agent 协作语义

- **FR-TC-17（M）** 任务中引用空间文档：composer 文件选择器增加「团队空间」源（树形选择，仅列有权文档）；引用内容按需拉取（全文或分块）。
- **FR-TC-18（M）** Agent 写回：任务产物（MD/CSV/HTML/文件）一键或按指令落到指定空间路径；对既有 MD 的修改默认走修订建议（FR-TC-09 语义），组织策略可放开为直接写（记录审计）。
- **FR-TC-19（S）** 空间活动流：谁在何时新建/修改/接受了什么（审计联动）。

### 3.7 横切

- **FR-TC-20（M）** 离线降级：服务端不可达时空间只读（本地缓存可浏览），恢复后增量同步；编辑中冲突按文档类型策略处理（MD=服务端权威提示刷新；HTML=CRDT 自动合并）。
- **FR-TC-21（M）** i18n 8 语言；搜索：空间内文档标题/内容全文检索（标题+MD/CSV 正文）。
- **FR-TC-22（S）** 回收站恢复；空间归档。

## 4. 范围裁决（明确不做）

| 事项 | 裁决 |
|---|---|
| Word/Excel/PPT 的「人机双写」 | **不做**（Workbuddy 依赖腾讯文档引擎；自研工程量不成比例）。Office 文件在空间内仅预览/下载/Agent 经工具处理（联动模块 06 的 PPT 导出可入空间） |
| MD 的多人**同时**编辑（CRDT） | v1 不做：MD 的协作模型是「评论+修订建议」，串行写入天然安全；MD CRDT 列 P6 评估 |
| 外部公开网站发布 | v1 仅「组织内/链接受邀」；对外发布页 C 级 |
| 跨组织空间共享 | 不做（组织边界=安全边界） |

## 5. 非功能需求

| # | 需求 |
|---|---|
| NFR-TC1 | 并发：单空间 50 成员在线、10 人同时编辑同一 HTML 不丢字（CRDT 收敛测试）；评论/修订操作 P95 <300ms 服务端响应 |
| NFR-TC2 | 文档规模：单 MD ≤5MB / 2 万行；CSV ≤50MB / 10 万行（超出引导拆分）；树深度 ≤10 层、单空间节点 ≤5000 |
| NFR-TC3 | 保密：空间内容传输 TLS、存储落既有交付物卷；审计事件全量记录（谁读了什么/谁改了什么/谁接受了修订） |
| NFR-TC4 | 一致性：修订建议应用与评论锚定在并发编辑下的冲突率 <1%，冲突必须显式提示而非静默丢失 |

## 6. 里程碑与验收

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M-TC1 | 空间/文档树/权限四档/邀请链接/上传与新建 | FR-TC-01~07；权限矩阵集成测试逐条通过 |
| M-TC2 | MD 审阅模式（评论 + AI 修订建议 + 按评论修订 + 撤销栈） | FR-TC-08~11、17~18；「划词→建议→逐条接受」全链路 E2E；并发修订冲突提示正确 |
| M-TC3 | HTML 协同（CRDT + presence）+ CSV + 剪藏 + Agent 直落 | FR-TC-12~16、19~22；10 人同时编辑 HTML 收敛性测试；Gate TC |

**Gate TC（模块出口）**：全部 M 级验收；试点团队（≥8 人）2 周真实项目空间使用：≥3 个空间、≥50 份文档、≥100 条评论、≥30 条修订建议（接受率数据回收）；Agent 权限一致读取渗透测试（越权尝试全部被拒且报错可读）；服务端安全自查（权限矩阵/注入/上传扫描）通过。

## 7. 名词术语

| 术语 | 定义 |
|---|---|
| 团队空间（Space） | 组织内的资料库单元：文档树 + 成员权限 |
| 修订建议（Revision Suggestion） | AI 产出的「原文/改后」对照提案，接受后才写入正文 |
| 锚定（Anchor） | 评论/修订与原文位置的绑定（段落序号 + 选区文本摘要，见 SPEC §3.3） |
| 按评论修订 | AI 读取全部评论自动产出修订建议集的功能 |
| presence | 协同编辑中的在线成员光标/选区可见性 |
