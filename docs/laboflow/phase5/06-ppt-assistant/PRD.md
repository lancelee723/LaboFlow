## 1. 背景与两个关键问题的回答

### 1.1 业务背景

咨询行业交付成果的核心方式是**信息密度高、数据驱动、专业美观的 PPT**。ZCode/Workbuddy/Autoclaw 均宣称能产出高质量 PPT；原型产品 Pi Desktop 亦有类似能力倾向。本模块定义 LaboFlow 的 PPT 能力路线。

### 1.2 关键问题一：LaboFlow 现在的 PPT 制作能力如何？

**结论：新仓库（laboflow-v2）当前 PPT 能力为零；冻结仓库（v1）有一条已验证的保底管线，但只是「基线」。**

- **v1 冻结仓库（已验证的蓝本）**：`SlideService`（主进程 Node 服务）——`$slides <主题>` 指令拦截 → `parseOutlineInput` 大纲规范化（版式 title/bullets/data/matrix）→ `renderSlideHtml` 逐页 HTML（预览概念）→ `exportPptx` 经 **pptxgenjs**（主进程 `require('pptxgenjs')` 懒加载，**不是 run_node 技能**）导出**文本框级可编辑 PPTX**（zip 结构断言测试过），产物登记 `kind='slides'` 带版本链。**未实现**：LLM 大纲方案、模板库（SPEC 设计了 8 模板，代码只有 4 种版式枚举）、预览翻页器、PDF/PNG/HTML 导出、组织模板包。
- **v2 新仓库**：pivot 决策「智能特性暂不移植」——零 PPT 代码、零相关技能（勘察确认无任何 pptx/slide 代码）。

### 1.3 关键问题二：PPT-Master 能否集成？——**能，裁决为「技能包 vendor 集成」，作为高质量路线的核心引擎**

[PPT-Master](https://github.com/hugohe3/ppt-master)（53.7k stars，v6.3.2）本质是**Claude-Code 式 Agent 技能包**：`SKILL.md` + 路由工作流 + 确定性 Python 工具链。管线：**规划（Strategist 产出 design_spec.md + spec_lock.md 契约）→ 生成（Executor 逐页手写 SVG，质量门禁）→ 转换（svg_to_pptx.py：SVG→原生 DrawingML）**，产出**原生可编辑 .pptx**（图表/表格为可编辑形状，可选数据驱动原生图表对象；LaTeX→OMML；支持模板蒸馏与自有模板）。

**可行性判断**：

| 维度 | 结论 |
|---|---|
| 许可 | MIT（核心 SVG→PPTX 路径全 MIT 依赖）。**注意**：可选 PDF 转换依赖 PyMuPDF（AGPL-3.0）——**集成时禁用该路径**即规避；pandoc（GPL）回退同理不用 |
| 形态匹配 | LaboFlow 的 agent 恰好是「Claude-Code 式循环 + shell + 文件 IO」——技能包是天然兼容的承载（读 SKILL.md → 选路由 → 跑 Python 脚本），无协议改造 |
| 运行时 | Python 3.10+ + 19 个 pip 依赖；需系统 Python 或应用引导安装（uv venv） |
| 模型要求 | 设计上推荐 ~1M 上下文强模型（Kimi K3/Claude 级）；LaboFlow 组织网关的长上下文模型（GLM/Kimi/Qwen-Max 等）可满足，模型不足时质量下降而非失败 |
| 风险 | 单人维护（pin 版本对冲）；首次运行需装依赖（引导向导对冲）；attribution_guard 需保留声明文件 |

**集成路径（详见 SPEC §3）**：vendor `skills/ppt-master/` 目录为内置技能（pin 固定版本）→ 应用引导 Python 运行时 → 把其脚本边界（规划/渲染/导出/质检）包装为受控 agentTools → 幻灯片工作台 UI 呈现大纲/预览/导出。**不 fork 其代码、不改造其内部**，升级=换 vendor 目录重跑适配测试。

### 1.4 分层能力模型（产品路线）

| 层 | 能力 | 引擎 | 定位 |
|---|---|---|---|
| **L1 基线** | 大纲→逐页→**可编辑 PPTX** 导出（轻量、秒级、免 Python） | pptxgenjs（v1 蓝本回迁） | 快速草稿/迭代；兜底 always works |
| **L2 高质量** | **PPT-Master 管线**：规划契约→逐页 SVG→原生 DrawingML PPTX；模板蒸馏；图表/公式原生对象 | vendor 技能包 + Python 工具链 | 咨询级正式交付（本模块主菜） |
| **L3 工作台** | 大纲编辑、逐页预览、模板库、风格统一、版本与产物链、组织模板包 | LaboFlow UI | 人的掌控面（两引擎共用） |

### 1.5 承载形态裁决（插件优先，R5-10）

**全部 L1/L2/L3 能力收敛于一个内置插件 `laboflow.slides`**（`contributes.agentTools + skills + views + settings`，先例=随附的 `pi.browser`/`pi.computer` 插件）：

- **主干零改动目标**：幻灯片工作台经 `contributes.views` 进工作面板（插件视图既有机制）；设置项经 `contributes.settings`；Python 运行时管理器住在插件进程/插件数据目录；升级与卸载整体走插件机制。
- **例外清单（全部主干触点，逐项评审）**：① 产物登记复用 `artifacts` 既有 RPC（无改动）；② 会话流新增「大纲确认卡/翻页器」两个渲染组件挂进既有卡片体系（渲染层扩展点，非引擎改动）。除此之外不得触碰 `electron/main/index.ts` 主干与 host-core。

## 2. 用户与场景

### 2.1 核心用户故事

- US-P1 作为顾问，我把研究结论文档拖进会话说「做成 20 页以内的汇报 PPT」——助手先给大纲方案（页标题/版式/数据要点），我确认后逐页生成，预览翻页检查，导出**可编辑 PPTX**（PowerPoint 打开元素可改）。
- US-P2 作为顾问，客户有模板规范——我把公司的 PPT 模板给助手「蒸馏」成风格契约，此后所有 PPT 按此风格生成；组织 IT 也可把模板包下发给全员。
- US-P3 作为顾问，我对某页不满意，选中该页说「这页改成瀑布图+三个要点」——只重生成该页，其余不动。
- US-P4 作为顾问，我用「@PPT 制作师」专家下任务（联动模块 01），它直接调 L2 管线产出初稿并给我修改建议。
- US-P5 作为顾问，赶时间只要个草稿骨架——用 L1 秒出可编辑初稿自己填。

## 3. 功能需求

### 3.1 会话级生成体验（入口）

- **FR-PPT-01（M）** 自然语言入口：「做 PPT / 生成 slide」意图或 `$slides` 指令 → 进入 PPT 制作流（先大纲后生成，两段确认）；输入源：主题、MD/DOCX/CSV/PDF 材料、知识库引用（模块 05）。
- **FR-PPT-02（M）** 大纲方案：结构化大纲（页标题/版式/要点/数据来源建议/讲者备注要点）**先呈现可编辑**——增删页、改标题、调版式，确认后生成。
- **FR-PPT-03（M）** 双引擎选择：默认 L2（PPT-Master，质量优先），可切 L1（pptxgenjs，速度优先）；引擎对用户呈现为「精制/快速」二档，细节能力差异在说明页展示。
- **FR-PPT-04（M）** 逐页预览：翻页器（页缩略图条 + 当前页大图）；页级操作：重生成该页（带修改指令）、删除、移动顺序。
- **FR-PPT-05（M）** 导出：PPTX（两引擎均为可编辑）；L2 另支持 SVG 预览包导出；PDF 导出 v1 不做（规避 AGPL；用户可在 PowerPoint 自行另存）。
- **FR-PPT-06（M））** 产物链：生成的 deck 登记产物（kind=slides，版本链）；一键入交付物库/团队空间（联动既有交付物通道与模块 02）。

### 3.2 L1 快速引擎（pptxgenjs 基线回迁）

- **FR-PPT-07（M）** 大纲规范化（版式：标题页/要点/数据/矩阵/对比/时间线/引用/结束，≥8 种）→ 逐页渲染 → PPTX 导出；升级 v1 蓝本：LLM 大纲方案（结构化输出）替代固定三页模板；主题色/字体沿模板配置。
- **FR-PPT-08（S）** L1 模板：内置 ≥4 套基础主题（咨询蓝/极简灰/深色汇报/品牌自定义）。

### 3.3 L2 精制引擎（PPT-Master 集成）

- **FR-PPT-09（M）** Python 运行时引导：首次使用检测系统 Python 3.10+（或引导安装 uv + venv）→ 依赖预检与安装向导（国内镜像可配）→ 运行时状态在设置页可见。
- **FR-PPT-10（M）** 管线受控暴露：规划（design_spec/spec_lock 契约，呈现给用户确认）→ 分批生成（前 5 页早门禁 → 其余 → 终检，进度可见可中断）→ 转换导出（postflight 报告呈现）。
- **FR-PPT-11（M）** **合规约束**：禁用 PyMuPDF/pandoc 路径（PDF 转换路由不可达）；保留 attribution 声明文件；vendor 版本 pin，升级走独立评审。
- **FR-PPT-12（M）** 模板能力：支持用户自有 .pptx 模板（上传后按其风格生成）；**模板蒸馏**（参考 deck → Brand/Style/Layout 风格契约，存为可复用资产）。
- **FR-PPT-13（S）** 增强项（配置开关）：数据驱动原生图表/表格对象（`--native-charts-and-tables`）；讲者备注 TTS 旁白；多种画幅（16:9 之外：小红书图/长图）。

### 3.4 组织能力

- **FR-PPT-14（M）** 组织模板包：管理台发布（模板文件 + 蒸馏风格契约 + 使用说明），bootstrap 下发，成员生成时默认可选「公司规范」。
- **FR-PPT-15（S））** PPT 制作师专家联动：模块 01 预设专家的工具链绑定 L2 管线工具（专家卡片「示例任务」直达）。

### 3.5 横切

- **FR-PPT-16（M））** 成本与预算：L2 单次 deck 预估 token 显著高于普通会话（长上下文多轮），生成前成本预估提示；预算上限可配（超限中断保留已完成页）。
- **FR-PPT-17（M）** i18n 8 语言（SKILL 本体英文原文不动，路由说明/UI 全翻译）。
- **FR-PPT-18（S））** 幻灯片工作台面板：右侧工作面板 tab（大纲树/页缩略图/版本历史），与产物面板联动。

## 4. 非功能需求

| # | 需求 |
|---|---|
| NFR-P1 | L1 性能：20 页大纲→PPTX ≤60s（无模型等待时 ≤5s）；L2：20 页全管线 ≤20min（含模型生成，网络正常），进度心跳 ≥30s 一次 |
| NFR-P2 | 可编辑性验收：两引擎产物在 PowerPoint 2016+/WPS/LibreOffice 三端打开元素可选中编辑（抽检制） |
| NFR-P3 | 稳定：Python 子进程崩溃不影响主应用（隔离 + 重试 1 次）；中断后续跑（保留已完成页与契约） |
| NFR-P4 | 安全：Python 仅本地文件 IO + 白名单网络（图片搜索可关）；素材与产物不出本机（除模型 API） |

## 5. 里程碑与验收

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M-P1 | L1 基线回迁 + 大纲确认流 + 预览导出 | FR-PPT-01~08（L1 部分）；三端可编辑抽检 |
| M-P2 | PPT-Master vendor + 运行时引导 + 管线受控暴露 | FR-PPT-09~11、16；真实任务 20 页端到端；AGPL 路径封禁验证 |
| M-P3 | 模板/蒸馏/组织模板包 + 工作台 + 专家联动 | FR-PPT-12~15/17~18；Gate PPT |

**Gate PPT（模块出口）**：全部 M 级验收；双引擎对比评测（同任务双引擎各 5 份，顾问盲评 L2 ≥4/5「可直接微调使用」）；三端抽检 30 页零格式坏页；许可合规检查（PyMuPDF 未启用/attribution 完整/依赖清单归档）；既有 E2E 不回归。

## 6. 名词术语

| 术语 | 定义 |
|---|---|
| L1/L2/L3 | 快速引擎（pptxgenjs）/ 精制引擎（PPT-Master）/ 幻灯片工作台 UI |
| spec_lock | PPT-Master 的机器可读设计契约（色彩锚点/字体/图标库/逐页路由），生成期间锁定 |
| 模板蒸馏 | 从参考 PPT 提炼风格契约（Brand/Style/Layout）存为可复用资产的过程 |
| 早门禁 | PPT-Master 的分批生成检查点：前 5 页先出、质检通过再继续 |
| postflight | 导出后自检报告（元素映射完整性/字体/几何校验） |
