## 1. 背景与定位

### 1.1 业务背景

咨询顾问的时间被切碎在通勤、会议、差旅途中。「在手机上给它下任务，干完推回来」是高频刚需：地铁上让它把昨天的访谈纪要整理成洞察清单、午休时让它跑一版数据测算、下班前把周报初稿生成好。同时，大量工作是有节律的：每日晨报、每周行业扫描、月度数据刷新——这些应该**自动发生**，而不是等人想起来。

对标 Workbuddy 的「助理模式 + 自动化」双页设计；LaboFlow v1 冻结仓库已有 Scheduler（croner + 补跑语义 + 失败自停）与 BotBridge（信封/签名）蓝本，但新仓库（PI-Desktop fork）当前**调度器无触发逻辑、无 headless 执行、无本地 HTTP 服务**——本模块的首要工作是把这三块地基补齐。

### 1.2 产品定位

- **助理模式**：侧栏的「助理」页是所有远程渠道的**总控台**——顶部列出已连接通道，中间是**全渠道汇成一条**的对话历史（落盘保存，重启不丢），底部输入框可以直接跟助理对话（和在 IM 里 @它 一样，任务在这台电脑上执行）。
- **定时任务（自动化）**：升级现有「自动化」页——cron 定时、错过补跑、运行记录、批量开关/删除、从模板一键添加。

### 1.3 通道矩阵（本模块消费、模块 04 供给）

| 渠道 | 要不要公网 | 本期范围 | 说明 |
|---|---|---|---|
| **通用 Webhook** | 不要（本机） | ✅ 本模块 T53.3 | `POST /im/task` 同步返回 `{reply, files}`；iOS 快捷指令/自动化平台/脚本可接 |
| 飞书机器人 | 不要（WS 长连接） | 模块 04 | 填 app_id/app_secret 即用 |
| 企业微信机器人 | 不要（WS 长连接） | 模块 04 | 智能机器人 API 模式 |
| 微信公众号 | 要（经服务端中继） | 模块 04 | 组织部署则中继天然可用 |
| 企业微信群机器人/钉钉 | 不要 | C 级（后续） | 只推结果不收指令 |
| QQ / 微信 iLink | 不要 | C 级（后续） | 架构预留 ChannelAdapter 扩展点 |

## 2. 用户与场景

### 2.1 核心用户故事

- US-MC01 作为顾问，我在手机上（飞书/企微/快捷指令）发「帮我把 projects/客户A 下的访谈纪要汇总成洞察清单」，电脑上的 LaboFlow 执行，完成后把结果和文件推回手机。
- US-MC02 作为顾问，我打开侧栏「助理」，像聊天一样直接给助理下任务；所有渠道的往来记录汇成一条历史，重启后还在。
- US-MC03 作为顾问，我建一个定时任务「每个工作日 9:00 抓今天的 AI 行业新闻生成晨报」，错过的那次在下次启动时补跑一次。
- US-MC04 作为顾问，我用 iOS 快捷指令一键触发「生成本周周报」，同步拿到 `{reply, files}`。
- US-MC05 作为顾问，定时任务连续失败时它自动暂停并通知我，别一直空烧 token。
- US-MC06 作为项目经理，我从模板库一键添加「每周五 17:00 周报提醒」任务，改两个字段就能用。

## 3. 功能需求

### 3.1 助理模式（总控台）

- **FR-MC-01（M）** 侧栏新增「助理」页：顶部**已连接通道**列表（通道名/状态灯/快捷设置入口，未连接时显示引导卡）；中部**统一对话历史**（所有渠道 + 本页直接输入的任务与结果，落盘持久，重启不丢）；底部输入框（可直接派任务，等价于 IM 指令）。
- **FR-MC-02（M）** 助理会话模型：远程指令进入一个**持久的助理会话**（非一次性），保留上下文（「再补充一版按地区拆分」可指代上一轮）；用户可清空/归档助理历史；多条渠道并发指令排队串行执行并各自回复。
- **FR-MC-03（M）** 结果回推：任务完成把最终回复推回来源渠道；产出文件按通道能力回传（文件上传 ≤ 通道限额，超出转本地保存 + 路径告知）；长文本按通道限制分片。
- **FR-MC-04（M）** 执行过程可见：助理页与远程渠道都能收到「已开始/进行中（当前步骤摘要）/完成/失败」的状态消息；本机桌面通知同步（复用既有任务通知策略）。
- **FR-MC-05（S）** 指令词法：`状态`（查询运行中任务）、`停止 <任务号>`、`列表`（今日任务清单）三个内建指令。

### 3.2 通用 Webhook（本机 HTTP）

- **FR-MC-06（M）** 本机 HTTP 端点：`POST /im/task`，body `{message, secret?}`，**同步返回 `{reply, files}`**（files=绝对路径数组；执行中的流式日志不阻塞响应，长任务转异步模式：返回 `{taskId}` + `GET /im/task/:id` 轮询/`GET /im/task/:id/events` SSE）。
- **FR-MC-07（M）** 安全：默认仅绑定 `127.0.0.1`，端口可配（默认 3800）；密钥鉴权（HMAC-SHA256 或 body secret，常量时间比较）；可选「局域网开放」开关（显式确认 + 强制密钥）；CORS 关闭。
- **FR-MC-08（M）** 与 iOS 快捷指令/脚本兼容：响应 ≤30s 的同步语义；超时阈值可配；错误返回结构化 `{error: {code, message}}`。

### 3.3 定时任务（自动化升级）

- **FR-MC-09（M）** **cron 5 字段**（分 时 日 月 周）：支持 `*` `,` `-` `*/n` `1-30/5` `5/10`；周字段 `0` 和 `7` 都是周日；日与周同时写具体值时按标准 cron 取**或**（`0 9 1 * 1` = 每月 1 号或每周一）。**非法表达式当场报错**（越界如 `70 * * * *`、写反如 `5-1`、步长 0），绝不静默收下永不触发的任务。
- **FR-MC-10（M）** 编辑体验：结构化频率选择器（每 N 分钟/每小时/每天 at/每周几 at/每月几号 at/自定义 cron）双模式；下一步触发时间预览（未来 3 次自然语言展示）。
- **FR-MC-11（M）** **错过补跑**（每任务可关）：应用没开/睡眠错过触发时，下次启动把该跑没跑的**补一次**——
  - 一段时间错过多次也**只补一次**（补最近该跑的那次：补「这件事还没做」，不是重放闹钟）；
  - 最多回补 **24 小时**，更早的按过期丢弃；
  - 装机后**首次启动不补跑**（否则一上来重放全部历史）；
  - 补跑在启动后延迟 60s 静默执行并标注 `trigger='catchup'`。
- **FR-MC-12（M）** 不叠跑：上一轮未完成时本次触发跳过（记录 `skipped`，原因「上一轮仍在运行」）。
- **FR-MC-13（M）** 运行记录：每次触发一条（ok/failed/skipped/catchup + 用时 + token + 关联会话/产物链接）；连续失败 ≥3 次自动暂停并通知。
- **FR-MC-14（M）** 批量管理：多选开关/删除；**从模板添加**（内置模板：每日晨报/每周周报/每周行业扫描/每月数据刷新 + 用户「存为模板」）。
- **FR-MC-15（M））** 任务配置：绑定项目/会话（沿用）、模型与思考档、**无人值守权限策略**（见 3.4）、输出目的地（会话内/交付物库/团队空间，联动模块 02）。
- **FR-MC-16（S）** OpenAPI：`POST /api/schedules`（本机 HTTP 同端口暴露，与 /im/task 同鉴权域）。

### 3.4 无人值守权限策略（裁决 R5-6）

- **FR-MC-17（M）** 无人值守会话（定时/远程触发）的三档策略，任务级可配：
  - **严格**（定时任务默认）：ask 类工具调用**自动拒绝**并记录（任务继续，工具不可用）；
  - **降级**（远程指令默认）：ask 类工具调用**挂起任务** + 推送审批通知（消息中心 + 来源 IM 渠道）；30 分钟无响应自动拒绝并继续；
  - **宽松**：等同 auto（显式二次确认才允许保存）。
- **FR-MC-18（M）** 审批回路：挂起的工具调用推送卡片（工具名/参数摘要/diff 预览）；在本机通知、助理页、或来源 IM 回复「批准/拒绝」后恢复执行。

### 3.5 横切

- **FR-MC-19（M）** 本机在线状态：助理页与 IM 渠道展示「本机离线时指令将无法执行」提示；应用退出前有运行中任务时托盘气泡告知。
- **FR-MC-20（M）** i18n 8 语言。

## 4. 非功能需求

| # | 需求 |
|---|---|
| NFR-MC1 | 触发精度：定时触发与计划时间偏差 ≤60s（睡眠唤醒后 ≤5s 内评估）；tick 周期 30s |
| NFR-MC2 | 并发：助理会话与定时任务共享全局子代理并发闸门；同一任务不叠跑（数据保证，非 UI 约定） |
| NFR-MC3 | 可靠：任务状态机落盘（进程崩溃重启后运行中任务标记 interrupted 可手动重跑）；Webhook 服务崩溃自动重启 ≤3 次 |
| NFR-MC4 | 安全：密钥不明文落盘（host secrets）；日志脱敏（消息正文默认不进日志） |
| NFR-MC5 | 体量：定时任务上限 50（原 20 放宽）；运行记录保留 90 天滚动 |

## 5. 里程碑与验收

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M-MC1 | HeadlessAgentDriver + 调度器（cron + 补跑）+ 自动化页升级 | FR-MC-09~16；cron 解析器全量用例（合法/非法/或语义/步长）；补跑四规则集成测试 |
| M-MC2 | 通用 Webhook + 助理模式页 + 统一历史 | FR-MC-01~08；iOS 快捷指令实测一条；重启不丢历史 |
| M-MC3 | 无人值守权限策略 + 审批回路 + 模板 | FR-MC-17~20；三档策略 E2E；Gate MC |

**Gate MC（模块出口）**：全部 M 级验收；「手机（任一已接通道）下任务 → 本机执行 → 结果回推」端到端实测；睡眠唤醒补跑场景真机验证（macOS 合盖过夜模拟）；连续失败自停真实验证；既有 E2E 不回归。

## 6. 名词术语

| 术语 | 定义 |
|---|---|
| 助理会话 | 远程指令与助理页共用的持久会话，保留跨轮上下文 |
| 通用 Webhook | 本机 HTTP 端点 `POST /im/task`，外部（快捷指令/脚本/自动化平台）同步调用 |
| 补跑（catch-up） | 错过触发后在下次可用时补执行最近一次的语义 |
| 无人值守权限策略 | headless 会话中 ask 类工具调用的处置策略（严格/降级/宽松） |
| HeadlessAgentDriver | 主进程直接驱动 agent sidecar 执行回合的组件（不再依赖渲染进程发起点） |
