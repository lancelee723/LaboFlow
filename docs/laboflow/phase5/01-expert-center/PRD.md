## 1. 背景与定位

### 1.1 业务背景

咨询团队的核心资产是**方法论与经验**。顾问的重复性专业工作——行业扫描、数据测算、Slide 起草、访谈纪要结构化、交付物审阅——今天靠每次手写提示词或复用零散模板完成，质量不稳定、无法沉淀、无法在团队内复用。

对标产品 Workbuddy 已验证该模型（专家中心 + 我的专家 + 专家团）；LaboFlow v1（冻结仓库）亦实现了 ExpertService 蓝本（6 个内置专家模板、@专家指派、指挥官团队并行派发），但因 pivot 至 PI-Desktop fork 而未迁移。本模块在新核心上重建并升级。

### 1.2 概念模型（沿用 Workbuddy 的三层选型逻辑）

| 概念 | 定义 | 选型逻辑 |
|---|---|---|
| Skill | 能力 | 需要工具能力时用 |
| **专家** | 能力 + 经验：以「**人设 + 方法论 + 工具链**」定义的**独立 Agent**，以特定领域专家身份执行任务（角色切换机制） | 有一个明确的单点问题时用 |
| **专家团** | 多位专家 + 协作流程：由**团长**自动拆解、并行执行并整合交付（协作执行机制） | 任务复杂、需要多角色配合时用 |

### 1.3 专家与子代理（SubAgent）的概念裁决（v1.1 核心修订）

**专家不是子代理，两者是不同层次的概念，本模块不得混淆实现：**

| 维度 | 子代理（SubAgent） | 专家（Expert） |
|---|---|---|
| 本质 | **一个任务内**处理部分事务的并发代理 | **一个个独立的 Agent**，本身即可承接完整任务 |
| 生命周期 | 随父任务而生灭（后台存续至汇报完成） | 拥有**独立会话**：召唤成前台会话、派发成后台独立会话，会话持久可回访 |
| 上下文 | 继承父任务上下文，只做局部 | 自有完整上下文，从人设与方法论出发独立工作 |
| 工具 | 受 `SUBAGENT_ASSIGNABLE_TOOLS` 白名单限制（PI-Desktop 原生语义，**保持不动**） | 会话级**完整工具链**：专家声明的 Skill/MCP 绑定 + 既有权限模式管控 |
| 用户视角 | 过程细节（进度卡片） | 可对话、可追问、可复用的「人」 |

落地约束（详见 SPEC §1 架构决策）：

- 专家以**独立 Agent 会话**执行：前台召唤=人格化交互会话；@指派/专家团成员=后台独立会话（经共享的 headless 驱动启动，非子代理 Task 工具）。
- **不修改** PI-Desktop 子代理机制（定义、白名单、Task 工具族、面板）——子代理继续服务其原生场景（任务内探索/审阅/修测）。
- 专家与 Skill 的关系：Skill 提供工具与流程；专家决定**以什么身份、用什么方法论、遵循什么输出规范**来调用它们。一个专家可绑定多个 Skill 与 MCP 服务器（工具链）。

### 1.4 安全模型（产品红线，沿用 Workbuddy 声明语义）

> 专家本身**不主动获取系统权限**，仅处理用户主动提供的对话与上传文件。当配备了 Skill / MCP 时，才会在用户授权下间接访问文件或外部服务。

落地：专家定义中的工具链绑定必须显式声明；专家会话沿用既有三档权限模式（ask / accept-edits / auto）；后台派发的专家会话按无人值守权限策略执行（联动模块 03 裁决 R5-6）；专家无法提升权限；组织专家为只读副本。

## 2. 用户与场景

### 2.1 目标用户

| 画像 | 诉求 |
|---|---|
| 顾问（Analyst/Consultant） | 把重复专业工作交给稳定的专家角色；@一下就派活；结果可直接进交付流 |
| 项目经理（EM/ED） | 用专家团并行推进多角色任务（研究+数据+Slide）；成本可控可见 |
| 团队知识管理员 | 把团队方法论封装成组织专家，全员开箱即用、版本统一 |

### 2.2 核心用户故事

- US-E01 作为顾问，我想在专家中心按行业浏览预设专家，点「召唤」直接以战略规划分析师身份开一个会话，给我一份某行业的市场结构分析。
- US-E02 作为顾问，我想在任意会话输入 `@数据分析专家` 把清洗任务派给它后台跑——它以**自己的独立会话**工作（我可点开查看完整过程），完成后结果卡片回到当前会话，我继续当前工作。
- US-E03 作为顾问，我想回到上周与「战略规划分析师」的会话继续追问——专家会话是持久的，像同事的对话窗口一样。
- US-E04 作为顾问，我想让「咨询交付团」（团长 + 战略 + 数据 + PPT 专家）接一个完整交付任务，看到它自动拆解、成员并行、最终整合出结构化成果。
- US-E05 作为顾问，我想创建自己的专家（填人设、绑定 Skill 与 MCP、导出分享给同事）。
- US-E06 作为团队知识管理员，我想发布组织级专家「公司Slide规范工程师」，全员客户端自动出现只读副本，更新后版本提示。
- US-E07 作为项目经理，我想看到专家团每个成员的实时状态与 token 消耗，超预算时收到预警。

## 3. 功能需求

优先级：M（Must，本模块 Gate 必须）/ S（Should）/ C（Could，首批裁剪对象）。

### 3.1 专家中心（浏览与召唤）

- **FR-E-01（M）** 侧边栏新增「专家」入口，进入专家中心：专家与专家团卡片网格，支持按**行业分类**浏览（首发分类：通用/战略与组织/金融/先进制造/TMT/医疗健康）与关键字搜索。
- **FR-E-02（M）** 专家卡片展示：图标、名称、一句话能力介绍、擅长领域标签、2–3 个任务示例；专家团卡片额外展示团队成员列表与成本提示（「消耗通常为单专家 3–5 倍」）。
- **FR-E-03（M）** 「召唤专家」：从卡片一键创建**专家会话**——一个以该专家身份运行的独立交互会话（输入区上方常驻专家身份条，可随时更换/退出）；对话内可通过专家下拉（搜索 + 置顶 + 最近使用）切换专家。
- **FR-E-04（M）** 专家会话是**一等会话**：出现在会话列表（带专家标识），持久保存、可随时回到该专家继续；切换专家=确认后开新会话（专家团会话独占，对齐 Workbuddy 语义）。

### 3.2 我的专家（创建与管理）

- **FR-E-05（M）** 「我的专家」区：创建（表单向导）、编辑、复制、删除（停用）、启用/停用、置顶；支持**高级模式**直接编辑专家定义原文（Markdown）。
- **FR-E-06（M）** 专家定义双通道：① 表单向导（分步：基本档 → 人设与方法论 → 工具链 → 模型与预算），向导产物即一份标准定义文件；② 导入 `.md` 定义文件（兼容 v1 冻结仓库 Agent.md / Soul.md 双文档格式，导入时合并为单一定义）。
- **FR-E-07（M）** 专家定义模型（字段见 SPEC §2.1）：基本档（名称/行业/擅长标签/任务示例）+ **系统提示词正文**（人设 + 方法论 + 输出规范，单文档）+ 工具链绑定（Skills、MCP 服务器）+ 模型与思考档 + 单次预算上限。
- **FR-E-08（S）** 专家包分享：导出为 `.md` 定义文件（frontmatter + 正文 + 绑定声明），同事导入即用；导入时若绑定外部 Skill/MCP 缺失，显式提示并允许降级创建。

### 3.3 预设专家与专家团（首发内容）

- **FR-E-09（M）** 预设专家首发 6 个（用户指定 3 个 + v1 蓝本升级 3 个），随应用分发、不可删除、可被同名的个人专家覆盖提示：

| 预设专家 | 核心角色定义（一句话） | 关键方法论锚点 |
|---|---|---|
| **战略规划分析师** | 以麦肯锡合伙人视角做行业/市场结构与竞争分析，结论先行、金字塔论证、数据优先于形容词 | MECE 议题树、三层面增长、波特五力、市场测算 TAM/SAM/SOM |
| **PPT 制作师** | 以导演级演示顾问身份产出「一页一信息」的 slide 大纲与正文，联动模块 06 PPT 助手直接出可编辑 PPTX | 金字塔原理 slide 化、行动标题（Action Title）、图表选型决策树 |
| **数据分析专家** | 严谨的数据清洗/指标测算/归因分析师，表格优先、每个数字可溯源、假设显式列出 | 假设驱动拆解、口径对齐清单、敏感性分析 |
| 行业研究员 | 行业扫描/竞对/政策研究员，结构化列表 + 来源 + 确定性分级标注 | PEST、价值链分析、确定性分级（高/中/低） |
| 访谈洞察专家 | 定性研究员，访谈纪要结构化、洞察提炼、原文引用克制 | 访谈编码、洞察-证据配对 |
| 审稿人 | 合伙人级交付物评审，阻断性/建议性问题清单，犀利但可执行 | So What 测试、数据一致性核对、逻辑断点扫描 |

- **FR-E-10（M）** 预设专家团首发 2 个：**咨询交付团**（团长 + 战略规划分析师 + 数据分析专家 + PPT 制作师；整合策略=主持人综合）与**行业研究团**（团长 + 行业研究员 + 数据分析专家；整合策略=摘要合并）。
- **FR-E-11（C）** 预设内容随版本迭代扩充（行业包：金融尽调团、组织诊断团……），支持从插件市场分发预设专家包（以插件 `contributes` 机制装载，见 SPEC §3.6）。

### 3.4 专家团（协作执行）

- **FR-E-12（M）** 专家团执行流程可视化：召唤专家团 → 输入任务 → 团长产出**拆解计划**（子任务清单：成员、职责简报、依赖关系）供用户确认或直接执行 → 成员各自以**独立专家会话**并行执行（状态板：待命/执行中/已完成/失败）→ 团长**整合交付**（最终成果 + 各成员贡献摘要）。
- **FR-E-13（M）** 预算控制：专家团可设总 token 预算（默认 200k，可调）；消耗实时展示；触达 80% 预警、100% 停止未完成任务并产出已完成部分的综合报告。
- **FR-E-14（S）** 自定义专家团：选成员（≤6）、指定团长风格（拆解粒度：精细/粗放）、整合策略（主持人综合 / 摘要合并 / 按章节拼接）。
- **FR-E-15（S）** 成员失败不阻断团队（标记 failed，团长整合时说明缺口）；支持对单个成员「重跑」。

### 3.5 会话内指派（@专家）

- **FR-E-16（M）** Composer 输入 `@` 弹出专家选择器（搜索 + 置顶 + 最近使用 + 预设/我的/组织分组），选中后以 `@专家名 任务` 形式派发；派发启动该专家的**后台独立会话**（非子代理），执行卡片在当前会话流中展示进度，完成后可展开查看结果、点开专家会话查看完整过程、并继续追问。
- **FR-E-17（S）** 多专家串行指派：`@A 做X，然后 @B 基于结果做Y`（依赖自动识别，串行执行，中间产物传递）。

### 3.6 组织专家库（组织模式）

- **FR-E-18（M）** 服务端发布组织专家/专家团（管理台资产页扩展）；成员客户端经 `/org/bootstrap` 接收只读副本（source=org，「组织」徽标），自动安装与版本更新提示。
- **FR-E-19（S）** 组织专家与个人专家同名时：组织版本在工作会话（登录组织）优先，个人版在本地会话优先，UI 明示来源。

### 3.7 横切

- **FR-E-20（M）** 成本透明：专家/专家团每次运行的 token 消耗计入用量统计（联动用量页），运行卡片展示本次消耗。
- **FR-E-21（M）** i18n 8 语言；专家定义正文不翻译，UI 文案全量翻译。
- **FR-E-22（S）** 专家资产可备份导出（含预设副本的个人修改版）。

## 4. 非功能需求

| # | 需求 |
|---|---|
| NFR-E1 | 并发：后台专家会话全局并发上限可配（默认 3，设置可调 1–6）；专家团单团并行成员 ≤4，超出排队 |
| NFR-E2 | 隔离：每个专家会话进程与会话状态隔离（复用 PI-Desktop 会话机制）；专家工具可见性=专家声明工具链 ∩ 会话权限模式（服务端强制，不依赖提示词自觉） |
| NFR-E3 | 持久化：专家/专家团定义为 `.agents/` 下的 Markdown 文件（PI-Desktop 能力档案惯例），删除=停用（文件可回收） |
| NFR-E4 | 响应：专家中心首次打开 <500ms（本地缓存）；召唤到首个 token <3s（不含模型网络） |
| NFR-E5 | 安全：组织专家下发内容经服务端校验；专家包导入做 frontmatter 校验与大小限制（≤1MB/文档） |

## 5. 里程碑与验收

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M-E1 | 专家定义层 + 专家中心/我的专家 + 召唤会话 | FR-E-01~07；预设 6 专家可用；v1 双文档可导入；专家会话持久可回访 |
| M-E2 | @指派（独立会话派发）+ TeamRunner + 专家团 UI | FR-E-12~17；「咨询交付团」端到端：拆解→并行→整合 ≤10min（标准研究任务）；预算触顶正确停止 |
| M-E3 | 组织专家库 + 分享 + 打磨 | FR-E-08/18~22；试点团队发布 1 个组织专家全员可见；Gate E 全绿 |

**Gate E（模块出口）**：全部 M 级 FR 验收；5 名顾问试点 2 周，专家/专家团周均调用 ≥3 次/人；组织专家下发链路（发布→bootstrap→只读副本→版本更新）E2E 通过；**子代理既有行为零变更回归**（设置页/Task 工具/面板 E2E 不回归）；既有 E2E 不回归。

## 6. 名词术语

| 术语 | 定义 |
|---|---|
| 专家（Expert） | 「人设 + 方法论 + 工具链」封装的**独立 Agent**：拥有独立会话，可前台召唤或后台派发 |
| 专家会话 | 以专家身份运行的独立会话（交互或后台），持久保存 |
| 子代理（SubAgent） | PI-Desktop 原生机制：任务内处理局部事务的并发代理——**不是专家的实现机制** |
| 专家团（Expert Team） | 团长 + 多成员专家的协作编排，星型模型：拆解 → 并行（独立会话）→ 整合 |
| 团长（Leader） | 专家团的编排角色：产出拆解计划、分配子任务、最终整合交付 |
| 工具链 | 专家显式绑定的 Skill 与 MCP 服务器集合（安全模型：声明才可见） |
| 组织专家 | 服务端发布、bootstrap 下发的只读专家副本（source=org） |
