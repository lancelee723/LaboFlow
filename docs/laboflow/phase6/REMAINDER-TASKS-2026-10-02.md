## 6. 实机验收方法与标准（Computer-Use）

### 6.0 总则（适用于全部 AC 场景）

1. **驱动方式**：验收由 AI 代理以 computer-use 技能**黑盒驱动真实桌面实例**（点击/键入/滚动/截屏），模拟真人操作；CDP（`--remoteDebuggingPort`）仅作断言辅助（渲染层 DOM、协议层状态）。**插件视图 / WebContentsView 面一律用 OS 级 `screencapture` 取证**——CDP 的 `Page.captureScreenshot` 拍不到原生子视图（phase6 README 2026-10-02 记录的教训）。
2. **完整任务流，不许「跑一下」**：每个模块对应一个端到端真实用户任务（AC 场景），有前置状态构造、编号步骤、每步观察点；场景必须贯穿「输入 → 执行 → 状态变化 → 产物/回执」全链，禁止停留在页面渲染检查或默认空态。
3. **状态新鲜度（禁止吃昨天）**：每轮验收以 `{ts}` 时间戳创建**全新**的会话/空间/任务/项目/脚本稿并贯穿全程；**禁止复用昨日或历史产物作为通过证据**。每个场景至少含一个「状态翻转」断言——文件新增、记录新行（trigger/run/kind）、内容变更、状态机迁移、跨端同步到达——初始态截图不构成任何断言依据。
4. **日志与证据链**：每轮在 `docs/laboflow/phase6/acceptance/{ts}/` 归档：分步截图（命名 `ACxx-stepNN.png`）、应用日志、外部调用全程输出（如 curl）、产物文件清单、运行记录页快照。验收报告仿 `E2E-ACCEPTANCE-2026-09-30.md` 格式（结论表 + 证据清单 + 缺口如实列明）。
5. **失败处置**：任一断言失败 → 停轮、登记根因（RCA）→ 修复 → **整场景从头重跑**；不允许只补跑失败步骤后宣称通过。
6. **真实调用与成本**：场景中的 LLM 调用是真实计费调用（用户已配模型渠道）；每场景给出预算上限，超限视为环境异常停轮。实机验收每轮执行前向用户报备（对齐仓库 `verify:ui:*` 授权口径：用户批准本文档即批准方法学，单轮执行仍逐次确认）。
7. **通过标准**：场景全部步骤断言通过 + 证据链完整 = 该模块验收通过；任一步骤无证据或证据为初始态 = 不通过。模块 Gate（§5 M-R1~R4）以对应 AC 场景实机通过为准，代码级测试全绿只是入场券。
